1 git的最小配置

配置user信息

git config –global user.name ‘Tou’

git config –global user.email ‘wzl890123@163.com’

配置后，如果你变更版本信息将会记录并显示是谁变更了信息

global – 对当前用户所有仓库有效

local – 只对某个仓库有效

system – 对系统所有登录的用户有效

显示当前git的config配置

git config –list –local

git config –list –global

git config –list –system

对某个仓库设置特定的用户，而不用上面设置的全局用户

在仓库路径下

git config –add –local user.name ‘用户名’

git config –add –local user.email ‘邮箱’

对于重复配置出现多个name和email的情况，可以直接edit .git/config 文件对config信息直接做修改

8 commit.tree.blob三种对象之间的关系

commit代表一次工程的提交，可以看做是工程的一个版本

tree可以理解为文件夹(对于空文件夹git并不会追踪),blob可以理解为文件(blob不以文件名作为区分，只要文件内容相同则blob的哈希值也是相同的)

git add将新增修改加到暂存区中，object文件夹中会出现此次添加对应的多出的blob哈希文件(blob)

git commit提交此次修改后，object文件夹中会新增一个commit类型的哈希文件(commit)，新增blob文件所处文件夹信息的哈希文件(tree)和新增blob文件名信息的哈希文件(tree)

9 分离头指针(head detach)

在git checkout 切换分支时后面跟的不是分支名，而是某次commit的哈希值

就会出现分离头指针的提示。分离头指针==此时工作在一个无分支的情况下

如果在分离头指针状态下做了很多修改，并做了提交(commit)。此时切换到其他确实存在的分支，由于没有branch名字和之前的分离头指针状态挂钩，我们之前做的那些变更很可能被git当做垃圾清理掉。

分离头指针状态下做的commit,可以看到HEAD没有指向任何分支(master or whatelse)，而就叫HEAD

分离头指针，我们也可以这么用，我们仅仅是想做一些尝试性的修改，如果修改结果并不好，可以直接不理会，切换到其他分支，git就会帮我们自动做清理工作。

如果这个尝试是好的，我们想把这些修改保存为新分支则可以

git branch 新的分支名 分离头指针状态下commit的哈希值(3d4673)

25 git revert 回滚 和 git reset

首先我们先假设我们有一条这样的commit历史：

A1 —> A2 —> A3 —> A4 —> A5 —> A6

当前的最新提交是A6，git的HEAD指向A6。在某一天发现，A4以及之后的commit都不能要，这种情况怎么办

如果你的commit还没有push到远程仓库，并且你本地没有commit的内容也都不想要了

**git reset –hard HEAD~3 **

A1 —> A2 —> **A3 **—> A4 —> A5 —> A6(HEAD执行)

5 —> 4 —> 3 —> 2 —> 1 —> 0

–hard参数表示会清除所有没有commit的内容，并且会修改commit历史，也就是说A4，A5，A6的历史没了。可能大多数情况这样并不好，但是作为个人项目或者自己在一个branch上实验各种东西，这个是合适的

你的commit已经都push到了远端仓库，或者你不想修改commit历史，那么最好用git revert

git revert –no-commit HEAD~2^..HEAD

或者

git revert –no-commit HEAD~3..HEAD

这个范围revert还有一个等价的写法，就是：

git revert –no-commit HEAD HEAD1 HEAD2

要revert A4到A6，范围表示HEAD2^..HEAD 或者 HEAD3..HEAD。

m..n表示范围的话，开闭类似(m, n]，HEAD2^表示HEAD2的parent，所以等价HEAD~3。

–no-commit 表示revert之后不自动commit，意思是，你运行完这个命令，你的repo会revert这些代码，然后这些代码处于未commit状态，在你commit之前可以检查是不是你想revert的代码。

检查完毕一切ok,再commit这次revert，那么现在这个commit历史就是

A1 —> A2 —> A3 —> A4 —> A5 —> A6 —> B

没错，你的A4，A5，A6依然在历史里，新的B commit就是你revert掉A4，A5，A6之后的结果，其实就是A3的状态，但历史都保留了。

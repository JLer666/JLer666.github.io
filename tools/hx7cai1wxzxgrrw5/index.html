要实现git pull上游和git push上游分开设置，可以按照以下步骤进行操作：

首先，查看当前Git仓库的远程分支列表，使用以下命令：

git remote -v

这将列出所有已配置的远程仓库及其对应的访问地址。

指定pull操作的上游分支。假设要将本地分支与名为upstream-branch的上游分支同步，则可以使用以下命令：

git branch –set-upstream-to=upstream-branch

这将把upstream-branch设置为本地分支的默认上游分支。每次运行git pull命令时，会自动从该分支拉取最新的代码。

指定push操作的上游分支。要将本地分支推送到名为upstream-branch的上游分支，可以使用以下命令：

git push upstream HEAD:upstream-branch

这将把本地分支的最新修改推送到upstream-branch分支上。

如果需要在多个远程仓库中进行操作，也可以分别针对不同的远程仓库设置不同的上游分支。例如，如果想要将本地分支与名为origin-branch的远程分支同步，则可以使用以下命令：

git branch –set-upstream-to=origin/origin-branch

总结起来，实现git pull上游和git push上游分开设置的步骤如下：

查看远程分支列表，确定所需的上游分支名称和所属的远程仓库。

使用–set-upstream-to选项指定pull操作的上游分支。

在push命令中指定目标上游分支名称，例如git push upstream HEAD:upstream-branch。

可以为每个远程仓库分别设置不同的上游分支，并使用相应的名称在pull和push命令中引用它们。

如果您不想在进行合并之前先提交本地修改，可以使用git stash命令将这些修改保存到一个临时的储藏库中，然后再进行合并操作。具体步骤如下：

使用git stash命令将当前工作目录中的修改保存到一个临时的储藏库中。例如：

git stash save “temporary changes”

然后，使用git pull或git merge命令更新远程分支。如果有冲突，则需要在解决冲突之后再进行提交。

git pull origin feature-branch

合并完成后，使用git stash pop命令将之前保存在储藏库中的修改重新应用到本地分支上。如果有冲突，则需要手动解决冲突，并再次运行git stash pop命令。

git stash pop

最后，进行提交操作即可。如果之前没有进行过提交，则可以使用git commit命令来提交修改。

总结起来，合并前未提交修改的方便方法是：

使用git stash命令将修改暂存到临时储藏库中。

进行更新操作，如git pull或git merge。

使用git stash pop命令将之前保存的修改重新应用到本地分支上。

完成修改后进行提交操作，如git commit。

重构流程

1 将当前的重构开发主线分支freeze，基于最新的head分出去一个分支 或 给当前的分支打一个tag

2 将当前主线分支copy到本地的其他地方，git rest –soft 到上次freeze的位置 ，再将回退的改动做一个总的commit，则可以查看当前新版本和上次freeze位置的所有diff

3 down 远程主重构分支到本地，将diff黏贴到本地主重构分支，并逐个提commit

4 将本地同步后的主重构分支传到远端，并于远端主重构分支提mr

5 同步远端主开发分支的新feature到重构分支

设置pre-commit

在.git项目路径下放置.pre-commit-config.yaml 文件

pre-commit install

验证钩子是否安装成功#

ls -al .git/hooks/pre-commit

检查所有文件#

pre-commit run –all-files

或检查指定文件#

pre-commit run –files src/planning/kabutack/planner/…

(1) 强制跳过检查（不推荐）

如果紧急情况下需要跳过检查：

git commit -m “…” –no-verify

(2) 更新检查规则

修改 .pre-commit-config.yaml 后，更新钩子：

pre-commit autoupdate

pre-commit install –force

(3) 删除旧钩子（如果冲突）

如果存在残留的钩子文件：

rm -f .git/hooks/pre-commit*

pre-commit install # 重新安装

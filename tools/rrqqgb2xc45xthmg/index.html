unique_lock – 互斥锁（mutex）的封装类

互斥锁mutex

互斥：在任意时刻只能有一个线程持有互斥锁并访问共享资源。当一个线程已经获得了互斥锁，其他线程对该互斥锁的请求将会被阻塞，直到持有互斥锁的线程将其释放。

可重入性：同一个线程可以多次获取同一个互斥锁而不会导致死锁（deadlock），也就是说，互斥锁可以被递归地加锁和解锁。

公平性：互斥锁通常采用先到先得的策略来分配锁的使用权，**即等待时间最长的线程优先获得锁的使用权，**这样可以避免饥饿（starvation）情况的发生。

死锁风险：如果不正确地使用互斥锁，就可能会出现死锁的情况。例如，当一个线程在持有一个互斥锁的同时试图获取另一个互斥锁，而另一个线程正好持有这个互斥锁，那么两个线程都无法继续执行下去，从而导致死锁。

性能开销：由于互斥锁需要进行加锁和解锁操作，所以会带来一定的性能开销，尤其是在高并发的场景中。因此，在编写代码时应该尽可能地减少锁的使用，并且保证锁的作用范围尽可能小，以提高程序的并发性能。

std::recursive_mutex – 可重入互斥锁（recursive mutex）

继承自std::mutex，并添加了可重入性（即同一个线程可以多次获取该锁 – mutex中说的可递归地加锁和解锁）的支持。与普通的互斥锁不同，当一个线程多次尝试获取std::recursive_mutex时，只有第一次获得锁才会阻塞，后面的请求会累积在该线程上，并通过解锁操作来依次释放锁。

使用std::recursive_mutex可以避免死锁和其他竞争条件（race condition）的出现，尤其是在递归调用的情况下非常有用。例如，在一个递归函数中，可能需要多次获取同一个锁来保护共享资源。如果使用普通的互斥锁，则在递归过程中可能会出现死锁的情况，因为线程在持有锁的同时又试图获取同一个锁。而使用std::recursive_mutex则可以避免这种情况的发生，从而提高程序的鲁棒性和可靠性。

与std::mutex类似，std::recursive_mutex也提供了lock()、unlock()等方法来控制锁的获取和释放，以及try_lock()方法来尝试获取锁。此外，std::recursive_mutex还支持std::lock_guard和std::unique_lock等RAII（资源获取即初始化）类型的封装，使得锁的管理更加方便和安全。

需要注意的是，由于std::recursive_mutex支持递归调用，所以在使用时应该确保每次加锁和解锁成对出现，否则可能会导致严重的竞态条件和内存泄漏等问题。

std::async与furture对象

std::async 是C++11标准库中的一种工具，用于异步执行函数或函数对象，并返回一个 std::future 对象，允许在需要时获取结果。这个函数是在 头文件中定义的。

在 C++ 中，同步执行代码意味着程序会等待某个操作完成，然后再继续执行下一步操作。如果处理时间很长，这样做可能会导致程序挂起，直到操作完成为止。而异步执行可以避免这个问题，因为它允许程序在等待某些操作完成时继续执行其他操作。

std::async 提供了一种简单的方式来实现异步执行。它接受一个函数或函数对象作为参数，并返回一个 std::future 对象，表示将来将会获得该函数或函数对象的结果。当调用 std::future 对象的成员函数 get() 时，如果结果已经准备好，该函数会立即返回；否则，它会阻塞当前线程，直到结果变得可用为止。

std::async的第一个参数是一个策略，可以指定任务是立即在一个新线程中执行，还是延迟到调用future的get或wait方法时执行2。std::async的返回值是一个future对象，可以通过get或wait方法来获取或等待任务的结果。例如：

#include <iostream>
#include <future>
#include <thread>
#include <chrono>

int add(int a, int b) {
    std::this_thread::sleep_for(std::chrono::seconds(3));
    return a + b;
}

int main() {
    // 启动一个异步任务，立即在新线程中执行
    std::future<int> f1 = std::async(std::launch::async, add, 10, 20);
    // 启动一个异步任务，延迟到调用get或wait时执行
    std::future<int> f2 = std::async(std::launch::deferred, add, 30, 40);
    // 获取f1的结果，会阻塞等待
    std::cout << "f1 result: " << f1.get() << std::endl;
    // 获取f2的结果，会触发任务执行
    std::cout << "f2 result: " << f2.get() << std::endl;
    return 0;
}
f1 result: 30
f2 result: 70

调用get方法会阻塞当前线程，直到异步任务完成，并返回任务的结果或异常。调用get方法后，future对象会变为无效，不能再次调用get方法。如果想要多次获取结果，可以使用std::shared_future

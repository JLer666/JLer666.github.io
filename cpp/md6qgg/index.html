C++ memory primitives

(C++ 自带的一些与内存分配相关的函数和表达式(操作符?))

| 分配 | 释放 | 类属 | 是否可重载 |

| — | — | — | — |

| malloc | free | C函数 | 不可 |

| new | delete | C++表达式 | 不可 |

| ::operator new() | ::operator delete() | C++函数(操作符重载函数) | 可 |

| allocator::allocate()(为stl容器分配内存) | allocator::deallocate() | C++标准库STL | 可自由设计并搭配任何容器 |

下面对上面的四种方法都举个小例子使用一遍

    int *p1 = (int *)malloc(n * sizeof(int)); //分配n个int大小的空间
    free(p1);

    complex<int> *p2 = new complex<int>; //申请一个int型复数的空间
    delete p2;

    int *p3 = (int *)::operator new(n * sizeof(int)); //分配n个int大小的空间
    ::operator delete(p3);

//以下使用stl allocator 因为编译器不同使用上略有不同

#ifdef _MSC_VER
//以下两个函数都是非静态的(non-static)，需要通过对象(allocator的实例化临时对象 allocator<int>() 生命只在这一行)来调用
int *p4 = allocator<int>().allocate(3, (int *)0);
//分配3个int的空间 传入的第二个参数(int*)0并没有意义(但还是有作用的) 因为类型已经在模板实例化时指定了
    allocator<int>().deallocate(p4, 3);
#endif

#ifdef __BORLANDC__
//以下两个函数都是非静态的(non-static)，需要通过对象(allocator的实例化临时对象 allocator<int>() 生命只在这一行)来调用
    int *p4 = allocator<int>().allocate(5);
//分配5个int的空间 与MSC版本的区别是不需要传入 第二个无用参数(int*)0 因为设定了默认值
    allocator<int>().deallocate(p4, 5);
#endif

//GUN早期版本有alloc::
    void *p4 = alloc::allocate(512); //分配512个字节
    alloc::deallocate(p4, 512);

//较新的GUN版本 将风格改为与BOR和MSC较像的书写风格
#ifdef __GUNC__
//以下两个函数都是非静态的(non-static)，需要通过对象(allocator的实例化临时对象 allocator<int>() 生命只在这一行)来调用
    void *p4 = allocator<int>().allocate(9); //分配9个int的空间

基本构件之一new delete expression

1 new expression

Complex* pc = new Complex(1,2);//Complex为自己写的一个类

编译器会将上面这句话 转译为

Complex* pc;
try{//new 表达式的流程
    //1分配对应大小的空间
    void* mem = operator new(sizeof(Complex));//allocate  new表达式中调用了 operator new函数(因为自己没有定义Complex::operator new函数 所以这里式调用的默认全局operator new函数 这个源码在下面有写)
    pc = static_cast<Complex*> (mem);//cast
    //2 调用对象的构造函数
    pc->Complex::Complex(1,2);//construct  只有编译器可以这样直接调用构造函数 使用者是不能这样调用的(其实在VC6上这样是可以通过的)
    //可以用placement new完成对于一块已存在空间的构造
    //new(pc) Complex(1,2);
}
catch(std::bad_alloc)
{
....//allocation失败 不会调用构造函数
}

补充 通过指针来直接调用构造和析构函数

class A{
public:
    int id;
    A(int i ):id(i){cout<<”ctor id:”<<this->id<<endl;}
    ~A(){cout<<”dtor id:”<<this->id<<endl;}
};
//使用
A* pa = new A(1);
cout<<pa->id<<endl;//1
pa->A::A(3);//vc6编译成功ctor id=3   gcc编译失败
A::A(5);//vc6 编译成功ctor id=5 然后这个临变量在这句话结束后析构 dtor id=5  gcc编译失败

注意这里讲的是不能直接调用构造函数，因为这样只会产生一个临时对象 在这句话结束后就析构了 并没有什么意义。但是可以让临时变量作为右值，或者通过 类名 变量名(初始值)的方式来调用构造函数

A a = A(3);//是ok的 首先由A(3)生成一个临时的A类对象 再通过operator =拷贝给变量a

现在的大部分编译会直接优化这句为 为a生成一个对象，而不会再去生成一个临时对象

A a(3);//也是ok的 编译器也是先为a分配内存 再通过构造函数的初始化列表初始化成员变量(先于构造函数体内的执行) 调用构造函数

malloc系统还会分配一块cookie 其中会记录内存的长度

malloc分配了多长会记录在cookie上，free也会根据cookie中记录的长度来释放内存

//注意用了array new 就一定要用array delete

delete[] pca;//会调用3次析构函数 如果写成delete pca则只会调用一次析构函数

内存泄漏并不是发生在free内存释放上(因为malloc cookie准确记录了内存的长度 free可以完成完整的回收),而是发生在析构上。delete只会调用一次析构函数 而delete[]会调用相应的多次析构函数。在类内没有ptr member 不需要在析构中去回收这块额外申请的内存时，用delete还是delete[]没有影响。但是当类内有ptr member(比如string类) 需要在析构中去回收这块额外申请的内存时，调用了几次析构就回收了多少块这个额外申请的内存，如果new array但是只delete将会导致只回收了一块额外内存，而其余的都没回收导致内存泄漏。

因为array new只能调用默认构造，所以我们需要自己在之后调用一些设置成员变量值的成员函数来对每个对象完成真正的初始化。

我们也可以不用一些额外的设置成员变量值的成员函数(但是最好这么做)。而使用placement new来调用有参构造来完成初始化

A* buf =new A[3];//先构造A[0] 再构造A[1],A[2]
A* tmp = buf;
for(int i =0;i<3;i++)
	new(tmp++)A(i);//不能直接调用构造函数来设置初值但是可以通过placement new(在已经存在的内存上 构造对象所以placement new不会再去申请内存 而是直接在这块内存上直接调用构造函数)来调用构造 (这里是想调用有参构造)将i作为初值
delete[] buf;//析构的顺序是逆序的 先析构A[2]再析构A[1] ,A[0]再free这块内存

实际产生的内存大小不止40字节，在vc6中会为40字节的int数组的上下加上的cookie 4字节大 保存了这整块内存(涵盖了所有)的大小 60h =96= 32 + 4*10 +4+12 +4+4(再加上 上下cookie的大小)，还有一位用作on off状态的记录，以及在debugger模式下会产生橙色块的额外记录(分别为32和4字节)，和padding将这整块内存的大小补为16的整数倍。

int 不存在析构函数，但是含ptr member的类对象在delete中不全部析构(array delete)是会出问题的。sizeof(Demo)=12，并且Demo写了非默认析构函数(non-trivial dtor),在非默认析构函数中完成了对一些堆上内存的释放。当类中有非默认析构函数，通过array new创建对象数组所产生的内存中编译器还会多分配一个字节会录这个array的长度(就是下图中的这个3)。

很细节，

Demo* p = new Demo[3];//p指向00481c34
delete p;//此时p还是指向00481c34 指向了实际内容的起点
delete[] p;//编译器会让p指向3  00481c30 指向了array的长度

这就是为什么当写了非默认析构函数后,使用array new并且不array delete会出错的原因。含非默认析构函数的类array new会让编译器申请的内存布局中多出4个字节记录数组的长度，所以调用delete p指向了实际内容的起点 编译器并不知道array长3所以只能析构一次，而delete[]编译器会让p指向3 编译器也就知道了array的长度 也就能相应的执行3次析构。

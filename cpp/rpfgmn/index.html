chunk_alloc函数行为，当前战备池够20个对象大小，则直接返回20个对象大小的空间，并移动start_free指针来减少当前战备池的大小

 template <bool threads, int inst>
    char *
    __default_alloc_template<threads, inst>::
        chunk_alloc(size_t size, int &nobjs)
    {
        char *result;
        size_t total_bytes = size * nobjs;         //size为一个对象的大小 n为20
        size_t bytes_left = end_free - start_free; //当前战备池内剩下多少字节

        if (bytes_left >= total_bytes) //当前战备池内的大小满足 20个对象这个需求
        {
            //则返回这20个对象大小的内存
            //并减少对应的战备池大小
            result = start_free;
            start_free += total_bytes; //减少战备池大小
            //地址是向下增长的 start_free<=end_free
            return (result); //result 为原start_free-start_free+total_bytes这块连续空间
        }

当前战备池不够20个对象大小，但是至少能分配一个对象的大小，则计算战备池最多能分配多少个对象，就拿出多少的空间给调用者，并移动start_free指针来减少当前战备池的大小

        else if (bytes_left >= size) //当前战备池大小至少能分配一个对象的内存
        {
            // 先计算余下大小到底能分配多少个对象
            // 注意nobjs为引用传入在这里传出后 调用者就能知道究竟是分配了多少个
            // 对象的内存
            nobjs = bytes_left / size;
            total_bytes = size * nobjs;
            //余下的内存最多分配nobjs个对象 这nobjs个对象的总大小为total_bytes
            result = start_free;
            start_free += total_bytes; //减少战备池大小
            return (result);           //result 为原start_free-start_free+total_bytes这块连续空间
        }

当前战备池连一个对象的大小都分配不了，则当前的战备池算作碎片，先将当前的战备池交给对应大小的free_list链表管理。然后从小到大看管理大于当前申请size的free_list(链表数组中 在当前右边的地方)是否还有节点多余，有则借一个节点来加入到战备池中，以战备池的分割方式分一个size大小给用户，如果右边的链表也没有内存节点了，此时是穷途末路，拿不到内存了，申请失败。

失败后会跳到第一级分配器调用oom_realloc or alloc_handler 循环监控当前堆中是否有内存。

        else
        {
            //当前战备池大小连一个对象大小的内存空间都不够了
            //则需要去向系统申请新的内存空间 并且将当前pool作为碎片交给对应的链表管理
            //申请--(我们之前一直有提到的 2*20*sizeof(对象) + ROUNDUP(累计申请量>>4))
            //其中20*sizeof(对象)的空间返回给调用者，余下的交给内存池
            size_t bytes_to_get =
                2 * total_bytes + ROUND_UP(heap_size >> 4);
            // Try to make use of the left-over piece.
            if (bytes_left > 0) //当前pool是有内存的并非刚好用完 则这些内存就是碎片要交给对应的链表管理
            {
                //将碎片交给对应的链表管理
                obj *volatile *my_free_list =
                    free_list + FREELIST_INDEX(bytes_left);
                //start_free就是碎片的起始地址
                ((obj *)start_free)->free_list_link = *my_free_list; //将碎片插到对应链表的头之前
                *my_free_list = (obj *)start_free;                   //将碎片作为新的头节点
            }
            start_free = (char *)malloc(bytes_to_get); //去 malloc 2*20*sizeof(对象) + ROUNDUP(累计申请量>>4)
            //将新申请的这块内存的首地址 作为pool的新的起始地址start_free
            if (0 == start_free) //malloc 申请失败会返回0
            {
                //应对堆中内存不够 malloc申请失败的情况
                int i;
                obj *volatile *my_free_list, *p;
                //Try to make do with what we have. That can't
                //hurt. We do not try smaller requests, since that tends
                //to result in disaster on multi-process machines.
                //找当前size对应链表的右边的链表(右边链表中的节点内存都是大于size的) 看右边链表中是否
                //还有内存节点 有的话应急直接拿来用 切出1个size大内存返回给用户 余下的作为pool战备池
                //例如szie=80的话 -- 向右边 查看管理88,96,104,112大小的节点
                //因该从size+__ALIGN开始循环更合理，因为size链表肯定没节点 要不然也不会到当前这个地步
                for (i = size; i <= __MAX_BYTES; i += __ALIGN)
                {
                    my_free_list = free_list + FREELIST_INDEX(i);
                    p = *my_free_list;
                    if (0 != p) //有右边的链表 有多余的节点 我们拿来借用
                    {
                        //p为我们借用的那块内存节点的首地址(也是那条链表头节点的首地址)
                        *my_free_list = p->free_list_link; //p被借用了 那条链表更新头节点为下个节点
                        //借来的这块空间 放到战备池中！！！！ start_free指向这块首节地址
                        start_free = (char *)p;
                        end_free = start_free + i;
                        return (chunk_alloc(size, nobjs));
                        //进行递归调用 在下一层的调用中 就可以直接满足我们的要求
                        //在上面的两个if就return了对应空间的大小
                        //这个递归只会向下一层就return 不会继续深入了
                        //Any leftover piece will eventually make it to the
                        //right free list.
                    }
                }
                //右边的链表中也没有内存节点(别人也破产了 借不到东西) 穷途末路了
                //拿不到内存 调用第一级分配器 第一级分配器会调用handler(out of memory)循环请求内存
                //看是否有进程/线程刚好释放内存则可马上拿来填填补这个需求
                end_free = 0; //In case of exception.
                start_free = (char *)malloc_alloc::allocate(bytes_to_get);
                //This should either throw an exception or
                //remedy the situation. Thus we assume it
                //succeeded.
            }
            // malloc分配成功 分配了我们要求的bytes_to_get这样大量的内存
            heap_size += bytes_to_get;            //累计申请量
            end_free = start_free + bytes_to_get; //战备池池底
            //成功申请了bytes_left
            //进行递归调用 在下一层的调用中 就可以直接满足我们的要求
            //在上面的两个if就return了对应空间的大小
            //这个递归只会向下一层就return 不会继续深入了
            return (chunk_alloc(size, nobjs));
        }
    }

listc;//list为std 容器 G2.9对容器模板的分配器类型有一个默认参数就是alloc 所以这里在定义的时候，没有指定分配器类型 因为默认就是我们上面讲的alloc

c.push_back(Foo(1));//Foo(1)是个临时变量在这句话结束后就销毁了 是在栈上申请的 这里假设sizeof(Foo) <128

push_back时容器会调用分配器alloc去申请sizeof(Foo)不带cookie的堆上内存,申请好后 容器会调用placement new在这块堆上内存去拷贝构造这个Foo(1)对象(如果Foo没有写拷贝构造则就调用默认的拷贝构造)，因为list是链表 所以list节点对象 除了data(指这个拷贝构造后的堆上对象)外还有两个指针prev和next。

c.push_back(new Foo(2));//编译报错 元素类型不符

//我们想 容器添加堆上对象需要像下面这样操作

Foo* p = new Foo(2);

c.push_back(*p);//ok *p为堆上对象

new expression会调用operator new,如果没有重载Foo的operator new并且在op new中通过alloc分配内存 而不是通过malloc申请内存。那么这个new肯定就是通过malloc来申请内存，p对象是带cookie的。push_back时容器会调用分配器alloc去申请sizeof(Foo)不带cookie的堆上内存,申请好后 容器会调用placement new在这块堆上内存去拷贝构造这个p对象，最终在*p在容器中的拷贝是不带cookie的！！

下面讲下这个源码细节上的不足之处

先讲个建议学习的的点

1

if(nullptr == start_free)

if(nullptr != p)

if(1== nobjs)

其中start_free,p都是指针，nobjs是个int

我在写比较时习惯将 变量写在比较符的左边，但是建议写在右边

这么写是为了防止在右边写时写成start_free=nullptr,p=nullptr,nobjs=1少写了一个符号变为赋值，并且这种bug非常难查出来。而颠倒过来写当我们少写了一个符号 编译器会提醒我们。

2

197 size_t bytes_to_get = …

….

207 start_free = (char*)malloc( bytes_to_get )

207行才用这个变量 但是在197行就定义出来了，希望当我们207行才用，那么在206行定义出来更清晰。

3

obj* *my_free_list;//单个变量好看出 这是个二级指针 指针的指针

*obj my_free_list,p;//这句话编译器会翻译成下面这种

**obj *my_free_list, p;

obj my_free_list;obj* p;**

一个二级指针 一个一级指针，而我们通常会误认为my_free_list和p都是二级指针。

所以为了避免别人理解上的错误，最好写成两行

obj my_free_list;obj* p; 这种形式方便别人理解**

4

static void(set_malloc_handler(void(*f)()))()

上面这一行等同于下面两行

typedef void (*H)();

static H set_malloc_handle(H f);//一个返回值和参数都是 函数指针的函数声明

就和我们之前的new_handler的形式一样

typedef void (*new_handler)();

new_handler set_malloc_handle(new_handler p)throw();

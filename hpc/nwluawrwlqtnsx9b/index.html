CUDA编程模型为应用和硬件设备之间的桥梁，所以CUDA C是编译型语言，不是解释型语言，OpenCL就有点类似于解释型语言，通过编译器和链接，给操作系统执行（操作系统包括GPU在内的系统）

程序和编程模型实现之间的抽象结构：

CUDA编程模型利用GPU架构的计算能力提供了两个特有功能：

通过层次结构在GPU中组织线程的方法

通过层次结构在GPU中访问内存的方法

设计解析数据和处理数据的函数，组织并发线程

多CPU和GPU环境，每个GPU和CPU的内存都由一条PCIe总线隔开。强调 主机为CPU及其内存(主机内存)和设备为GPU及其内存(设备内存)。代码中主机内存中的变量以h_为前缀，设备内存中的变量以d_为前缀(感觉改为后缀更好)。

注意这两个内存从硬件到软件都是隔离的，从CUDA 6.0开始NVIDIA提出了统一寻址(Unified Memory)的编程模型改进，链接主机内存和设备内存空间，可以使用单个指针访问CPU和GPU内存无需彼此之间手动拷贝数据。

内核(kernel)是CUDA编程模型的重要部分，其代码在GPU上运行，在GPU线程上编写核函数。

大多数情况下，主机可以独立对设备进行操作，内核启动后管理权立刻返回给主机，释放CPU来执行设备上运行的并行代码。可以将C和CUDA C代码放在同一个源文件中。nvcc会分别为主机和设备生成可执行代码。

从host的串行到调用核函数（核函数被调用后控制马上归还主机线程，也就是在第一个并行代码执行时，很有可能第二段host代码已经开始同步执行了），可以理解为主机和设备完全异步，如果主机不等待设备结果可以直接跑完整个主机程序不受阻塞。

内存管理#

核函数在设备上运行，CUDA运行时负责分配与释放设备内存以及主机与设备间的通信。内存管理在传统串行程序是非常常见的，寄存器空间，栈空间内的内存由机器自己管理，堆空间由用户控制分配和释放，CUDA程序同样，只是CUDA提供的API可以分配管理设备上的内存，当然也可以用CDUA管理主机上的内存，主机上的传统标准库也能完成主机内存管理。

| 标准C函数 | CUDA C 函数 | 说明 |

| :—: | :—: | :—: |

| malloc | cudaMalloc | 内存分配 |

| memcpy | cudaMemcpy | 内存复制 |

| memset | cudaMemset | 内存设置 |

| free | cudaFree | 释放内存 |

我们先研究最关键的一步，这一步要走总线的。cudaMemcpy负责主机和设备间的数据传输。

cudaError_t cudaMemcpy(void * dst,const void * src,size_t count,
  cudaMemcpyKind kind)

kind负责指定内存的拷贝方向，kind有以下几种：

cudaMemcpyHostToHost

cudaMemcpyHostToDevice

cudaMemcpyDeviceToHost

cudaMemcpyDeviceToDevice

函数执行成功，则会返回 cudaSuccess 否则返回 cudaErrorMemoryAllocation。通过char* cudaGetErrorString(cudaError_t error)翻译打印错误信息。

在GPU内存层次结构中最主要的是两种内存，全局内存和共享内存，全局类似于CPU的系统内存(Mem)而共享内存类似于CPU的多级缓存(Cache)，GPU的共享内存可又CUDA C内核直接控制。下图是一个简化的GPU内存结构。

下面通过一个两数组相加(element wise add)的例子来学习如何在主机和设别间传输数据

/*

* https://github.com/Tony-Tan/CUDA_Freshman

* 3_sum_arrays
\*/
#include <cuda_runtime.h>
#include <stdio.h>
#include "freshman.h"

void sumArrays(float * a,float * b,float * res,const int size)
{
  for(int i=0;i<size;i+=4)
  {
    res[i]=a[i]+b[i];
    res[i+1]=a[i+1]+b[i+1];
    res[i+2]=a[i+2]+b[i+2];
    res[i+3]=a[i+3]+b[i+3];
  }
}
__global__ void sumArraysGPU(float*a,float*b,float*res)
{
  int i=threadIdx.x;
  res[i]=a[i]+b[i];
}
void initialData(float *ip,int size)
{
    time_t t;
    srand((unsigned int) time(&t));
    for(int i = 0;i < size;++i)
    {
        ip[i] = (float) (rand() & 0xFF)/10.0f;
    }
}
int main(int argc,char **argv)
{
  int dev = 0;
  cudaSetDevice(dev);

  int nElem=32;
  printf("Vector size:%d\n",nElem);
  int nByte=sizeof(float)*nElem;
  float *a_h=(float*)malloc(nByte);
  float *b_h=(float*)malloc(nByte);
  float *res_h=(float*)malloc(nByte);
  float *res_from_gpu_h=(float*)malloc(nByte);
  memset(res_h,0,nByte);
  memset(res_from_gpu_h,0,nByte);

  float *a_d,*b_d,*res_d;
  CHECK(cudaMalloc((float**)&a_d,nByte));
  CHECK(cudaMalloc((float**)&b_d,nByte));
  CHECK(cudaMalloc((float**)&res_d,nByte));

  initialData(a_h,nElem);
  initialData(b_h,nElem);

  CHECK(cudaMemcpy(a_d,a_h,nByte,cudaMemcpyHostToDevice));
  CHECK(cudaMemcpy(b_d,b_h,nByte,cudaMemcpyHostToDevice));

  dim3 block(nElem);
  dim3 grid(nElem/block.x);
  sumArraysGPU<<<grid,block>>>(a_d,b_d,res_d);
  printf("Execution configuration<<<%d,%d>>>\n",block.x,grid.x);

  CHECK(cudaMemcpy(res_from_gpu_h,res_d,nByte,cudaMemcpyDeviceToHost));
  sumArrays(a_h,b_h,res_h,nElem);

  checkResult(res_h,res_from_gpu_h,nElem);
  cudaFree(a_d);
  cudaFree(b_d);
  cudaFree(res_d);

  free(a_h);
  free(b_h);
  free(res_h);
  free(res_from_gpu_h);

  return 0;
}

这里要特别强调几点：

1 cudaMemcpy将主机内存拷贝到GPU的全局内存中

2 cudaMemcpy调用会阻塞主机运行

3 数据被拷贝到GPU的全局内存后，主机端调用核函数sumArraysGPU，在调用后的控制权立刻被传回主机不会阻塞主机运行。内核函数与主机程序异步

4 使用CUDA C新手常犯的错误是对不同内存空间的不恰当引用，混用设备和主机的内存地址，malloc和cudaMalloc分配的地址有很小概率可能相同但是其对应的物理内存是完全不同的一个在主机内存，一个在设备内存。

总结一下cuda中涉及的各种内存特点#

| 内存类型 | 物理位置 | 速度排名 | 作用域 | 生命周期 | 主要用途 |

| :— | :— | :— | :— | :— | :— |

| 寄存器 | 片上 | 1 (最快) | 单个线程 | 线程 | 存储频繁使用的线程私有变量 |

| 共享内存 | 片上 | 2 | block内所有线程 | block | 线程块内线程间高效通信与协作 |

| 常量内存 | 板载 (带缓存) | 3 | 所有线程 + Host | 程序 | 存储所有线程只读的常量数据 |

| 纹理内存 | 板载 (带缓存) | 4 | 所有线程 + Host | 程序 | 优化具有空间局部性的非对齐/随机访问 |

| 全局内存 | 板载 | 5 (最慢) | 所有线程 + Host | 手动管理 | 存储大量数据，用于主机与设备间或线程块间数据交换 |

| 本地内存 | 板载 | 5 (同全局内存) | 单个线程 | 线程 | 当寄存器不足时，存储线程私有的大数组或变量 |

寄存器是每个线程私有的、速度最快的内存。

申请方式：在核函数中，编译器会自动将简单的局部变量（如 int index;）分配到寄存器中，无需手动申请。

注意事项：寄存器数量有限。如果变量过多或定义了大型结构体/数组，编译器可能会将部分变量“溢出”到速度慢得多的本地内存中

共享内存是块内线程共享的片上内存，用于线程协作。

静态申请：在核函数内使用 __shared__关键字。

动态申请：使用 extern __shared__声明，并在启动核函数时指定大小。myKernel«<grid, block,** sizeof(float) * 128**»>();// 启动核函数，第三个参数指定动态共享内存的字节数

使用共享内存后，需调用 __syncthreads()来确保块内所有线程在继续执行前已完成对共享内存的读写

全局内存(线程)是容量最大、最常用，但速度最慢的内存，用于存储主要数据。优化全局内存访问的关键是促成合并访问，即让一个线程束（Warp）的线程连续访问内存

// 1. 在Host端申请设备全局内存
float *d_data;
cudaMalloc((void**)&d_data, size_in_bytes);
// 2. 将数据从Host拷贝到Device
cudaMemcpy(d_data, h_data, size_in_bytes, cudaMemcpyHostToDevice);
// 3. 在核函数中，通过指针访问
__global__ void kernel(float *data) {
    int idx = threadIdx.x + blockIdx.x * blockDim.x;
    data[idx] = ...; // 访问全局内存
}
// 4. 使用完毕后，务必释放内存
cudaFree(d_data);

**本地内存(核函数内定义的作用于为单个线程的较大临时变量)**实际上是全局内存的一部分，当寄存器不够用时，编译器会自动将变量溢出到此位置。程序员无法直接控制，但应意识到其存在并尽量避免（例如，避免在核函数中定义过大的数组）

常量内存是只读内存，适合存储所有线程都需要读取的常量。

// 1. 在文件作用域声明常量内存变量（通常是64KB）
__constant__ float constData[1024];
// 2. 在Host端，使用专用函数拷贝数据初始化
float h_data[1024] = {...};
cudaMemcpyToSymbol(constData, h_data, sizeof(h_data));
// 3. 在核函数中直接读取
__global__ void kernel() {
    float value = constData[threadIdx.x]; // 只读
}

纹理内存是为图形处理设计的一种只读内存，对具有空间局部性的非连续访问有优化。纹理内存支持硬件插值和多种寻址模式，适用于图像处理等场景

// 1. 定义纹理引用
texture<float, 1, cudaReadModeElementType> texRef;
// 2. 创建并绑定CUDA数组
cudaArray* cuArray;
cudaMallocArray(&cuArray, &texRef.channelDesc, width, height);
cudaMemcpyToArray(cuArray, 0, 0, h_data, size, cudaMemcpyHostToDevice);
cudaBindTextureToArray(texRef, cuArray);
// 3. 在核函数中通过纹理获取函数读取
__global__ void kernel() {
    int x = threadIdx.x + blockIdx.x * blockDim.x;
    float value = tex1Dfetch(texRef, x); // 使用纹理读取
}
// 4. 使用完毕后解绑并释放
cudaUnbindTexture(texRef);
cudaFreeArray(cuArray);

线程管理#

当主机端运行核函数在设备端运行，此时设备会根据提供的«<»>内参数组织线程，并且每个线程都执行核函数指定的语句。 CUDA提出两层的线程层次结构，由线程块(Block)核线程网格(Grid)构成。

由一个内核(kernel 内核函数)启动所产生的所有线程统称为网格(grid)，同grid的所有线程共享相同的全局内存空间。gird由多个thread block构成，block中包含一组线程，同一block内的线程协作可通过同步或共享内存实现，不同block内的线程不能协作是物理隔离的。

线程通过两个坐标变量进行索引 blockIdx(block在grid内的索引) threadIdx(block内的线程索引)

核函数预初始化索引变量，当执行核函数时CUDA运行时为每个线程分配blockIdx和threadIdx基于这些坐标，进行数据划分，分给不同线程。

坐标为3个无符号整数uint3含x、y、z三个字段 blockIdx.x .y .z threadIdx.x .y .z。CUDA可以组织三维的grid和block上图只展示了二维的grid和block

grid和block维度由两个内置变量决定

blockDim ,gridDim 类型为dim3，基于uint3定义，未指定的元素默认为1。都有三个维度.x .y .z 一般grid会被设定为二维，block会被组织为三维

gridDim 为grid中block的组织维度

blockDim 为block中thread的组织维度

dim3可在主机端指定，uint3仅在设备端执行可见不能在核函数运行时修改初始化完后不变

/*
\*1_check_dimension
\*/
#include <cuda_runtime.h>
#include <stdio.h>
__global__ void checkIndex(void)
{
  printf("threadIdx:(%d,%d,%d) blockIdx:(%d,%d,%d) blockDim:(%d,%d,%d)\
  gridDim(%d,%d,%d)\n",threadIdx.x,threadIdx.y,threadIdx.z,
  blockIdx.x,blockIdx.y,blockIdx.z,blockDim.x,blockDim.y,blockDim.z,
  gridDim.x,gridDim.y,gridDim.z);
}
int main(int argc,char **argv)
{
  int nElem=6;
  dim3 block(3);//含3线程的一维block
  dim3 grid((nElem+block.x-1)/block.x); // grid大小是block大小的倍数
  printf("grid.x %d grid.y %d grid.z %d\n",grid.x,grid.y,grid.z);
  printf("block.x %d block.y %d block.z %d\n",block.x,block.y,block.z);
  checkIndex<<<grid,block>>>();// <<<>>> 设定grid dim和block dim
  cudaDeviceReset();
  return 0;
}

主机端声明大小在启动内核前就定义了维度大小，设备端直接用blockDim.x,blockDim.y,blockDim.z, gridDim.x,gridDim.y,gridDim.z 访问内核中预初始化的维度大小(在设备端访问griddim和blockdim属性的数据类型是uint3不能修改的常类型结构，这里反复强调一下)。

启动CUDA核函数#

kernel_name«<grid dim,block dim»> (args list)

通过grid dim,block dim配置核函数使用的内核线程总数、以及配置线程布局

同block内线程可协作，不同block内线程不能协作。

设32个数据,每8个一块，启动4块布局如下图

由于设备内存是线性的(数据从主机端拷贝到设备端)通过blockIdx.x和threadId.x 在grid中标识唯一的线程，建立线程和数据元素之间的映射关系

这里再强调一下所有CUDA核函数的启动都是异步的，CUDA内核调用函数在运行函数第一句指令前就会马上把控制权返回CPU不会阻塞主机端代码。

可以通过一下cudaDeviceSynchronize函数显示强制主机端程序等待所有核函数执行结束。

cudaError_t cudaDeviceSynchronize(void);

一些CUDA运行时主机和设备间是隐式同步的，比如使用cudaMemcpy函数在主机和设备间拷贝数据时，主机端隐式等待数据拷贝完成后才能继续执行主机端程序， 首先需要等之前所有异步的核函数调用完成后 开始拷贝数据 数据拷贝完成后控制权才返回给主机端。

核函数编写#

核函数的声明

__global__ void kernel_name(argument list);

CUDA C中定义了一些如下限定符

| 限定符 | 执行 | 调用 | 备注 |

| :—: | :—: | :—: | :—: |

| global | 设备端执行 | 可以从主机调用也可以从计算能力3以上的设备调用 | 必须有一个void的返回类型 |

| device | 设备端执行 | 设备端调用 | |

| host | 主机端执行 | 主机调用 | 可以省略不写，默认是host的 |

有个特殊的情况就是有些函数可以同时定义为 device 和 host (两个限定符一起使用)，这种函数可以同时被设备和主机端的代码调用，主机端代码调用函数很正常，设备端调用函数与C语言一致，但是要声明成设备端代码，告诉nvcc编译成设备机器码，同时声明主机端设备端函数，那么就要告诉编译器，生成两份不同设备的机器码。

核函数有以下限制：

只能访问设备内存

必须void返回

不支持可变数量的参数

不支持静态变量

显示异步

并行程序中常见的一种现象：

把串行代码并行化时对串行代码块中的for消失，下面以一个向量加法为例

串行:

void sumArraysOnHost(float *A, float *B, float *C, const int N) {
  for (int i = 0; i < N; i++)
    C[i] = A[i] + B[i];
}

并行

__global__ void sumArraysOnGPU(float *A, float *B, float *C) {
  int i = threadIdx.x;
  C[i] = A[i] + B[i];
}

并行程序的循环体消失，使用线程坐标替换素组索引，且N是隐式外部定义启动N个线程。

  dim3 grid(nElem/block.x);
  sumArraysGPU<<<grid,block>>>(a_d,b_d,res_d);
  printf("Execution configuration<<<%d,%d>>>\n",block.x,grid.x);

  CHECK(cudaMemcpy(res_from_gpu_h,res_d,nByte,cudaMemcpyDeviceToHost));
  sumArrays(a_h,b_h,res_h,nElem);

  checkResult(res_h,res_from_gpu_h,nElem);
  cudaFree(a_d);
  cudaFree(b_d);
  cudaFree(res_d);

  free(a_h);
  free(b_h);
  free(res_h);
  free(res_from_gpu_h);

  return 0;
}

组织并行线程#

每一个线程是怎么确定唯一的索引，然后建立并行计算，并且不同的线程组织形式是怎样影响性能的，以矩阵加法为例。以一个8x6矩阵内存存储形式为例，以行优先方法在全局内存中进行线性存储。矩阵加法核函数中，一个线程通常被分配做一个元素的加法。

首先需要做的是通过块blockIdx和线程索引threadIdx计算矩阵元素索引，再从全局内存中访问此元素，涉及线程和块索引、矩阵中指定元素的坐标，全局线性内存中的索引

矩阵元素坐标

ix = threadIdx.x + blockIdx.x * blockDim.x

iy = threadIdx.y + blockIdx.y * blockDim.y

元素坐标映射到全局线性内存的索引

idx = iy * nx + ix

使用下面这段代码，打印线程索引、块索引、矩阵坐标、线性全局内存索引、相应元素值

#include <cuda_runtime.h>

  printf("thread_id(%d,%d) block_id(%d,%d) coordinate(%d,%d)"
          "global index %2d ival %2d\n",threadIdx.x,threadIdx.y,
          blockIdx.x,blockIdx.y,ix,iy,idx,A[idx]);
}

__global__ void sumMatrix(float * MatA,float * MatB,float * MatC,int nx,int ny)
{
    // 就是上文所用的划分方法
    int ix=threadIdx.x+blockDim.x*blockIdx.x;
    int iy=threadIdx.y+blockDim.y*blockIdx.y;

    if (ix<nx && iy<ny)
    {
      MatC[idx]=MatA[idx]+MatB[idx];
    }
}

int main(int argc, char **argv)
{
    printf("%s Starting...\n", argv[0]);

    // set up device
    int dev = 0;
    cudaDeviceProp deviceProp;
    CHECK(cudaGetDeviceProperties(&deviceProp, dev));
    printf("Using Device %d: %s\n", dev, deviceProp.name);
    CHECK(cudaSetDevice(dev));

    // set up data size of matrix
    int nx = 1 << 13;
    int ny = 1 << 13;

    int nxy = nx * ny;
    int nBytes = nxy * sizeof(int);
    printf("Matrix size: nx %d ny %d\n", nx, ny);

    // malloc host memory
    int *h_A, *h_B, *hostRef, *gpuRef;
    h_A = (int *)malloc(nBytes);
    h_B = (int *)malloc(nBytes);
    hostRef = (int *)malloc(nBytes);
    gpuRef = (int *)malloc(nBytes);

    // initialize data at host side
    double iStart = seconds();
    initialData(h_A, nxy);
    initialData(h_B, nxy);
    double iElaps = seconds() - iStart;
    printf("Matrix initialization elapsed %f sec\n", iElaps);

    memset(hostRef, 0, nBytes);
    memset(gpuRef, 0, nBytes);

    // add matrix at host side for result checks
    iStart = seconds();
    sumMatrixOnHost(h_A, h_B, hostRef, nx, ny);
    iElaps = seconds() - iStart;
    printf("sumMatrixOnHost elapsed %f sec\n", iElaps);

    // malloc device global memory
    int *d_MatA, *d_MatB, *d_MatC;
    CHECK(cudaMalloc((void **)&d_MatA, nBytes));
    CHECK(cudaMalloc((void **)&d_MatB, nBytes));
    CHECK(cudaMalloc((void **)&d_MatC, nBytes));

    // transfer data from host to device
    CHECK(cudaMemcpy(d_MatA, h_A, nBytes, cudaMemcpyHostToDevice));
    CHECK(cudaMemcpy(d_MatB, h_B, nBytes, cudaMemcpyHostToDevice));

    // invoke kernel at host side
    int dimx = 32;
    int dimy = 32;
    dim3 block(dimx, dimy);
    dim3 grid((nx + block.x - 1) / block.x, (ny + block.y - 1) / block.y);

    iStart = seconds();
    // 512x512,32x32  调整块尺寸 512x1024,32x16核函数运行速度几乎翻了一倍
    //                调整块尺寸 1024x1024,16x16核函数运行速度不如原
    sumMatrixOnGPU2D<<<grid, block>>>(d_MatA, d_MatB, d_MatC, nx, ny);
    CHECK(cudaDeviceSynchronize());
    iElaps = seconds() - iStart;
    printf("sumMatrixOnGPU2D <<<(%d,%d), (%d,%d)>>> elapsed %f sec\n", grid.x,
           grid.y,
           block.x, block.y, iElaps);
    // check kernel error
    CHECK(cudaGetLastError());

    // copy kernel result back to host side
    CHECK(cudaMemcpy(gpuRef, d_MatC, nBytes, cudaMemcpyDeviceToHost));

    // check device results
    checkResult(hostRef, gpuRef, nxy);

    // free device global memory
    CHECK(cudaFree(d_MatA));
    CHECK(cudaFree(d_MatB));
    CHECK(cudaFree(d_MatC));

    // free host memory
    free(h_A);
    free(h_B);
    free(hostRef);
    free(gpuRef);

    // reset device
    CHECK(cudaDeviceReset());

    return (0);
}

端到端的本质是什么？端到端的本质应当是感知信息的无损传递，目前感知输出的这些信息，都是对复杂驾驶场景的一种抽象，而且是人工定义的显式抽象。然而，对于一些非常见场景中，现在的显式抽象难以充分表达场景中会影响驾驶行为的因素，亦或是我们需要定义的任务过多过琐碎，也难以枚举尽所有需要的任务。所以端到端系统，提供了一种（也许是隐式）全面表示，希望能够自动地无损地将这样的信息作用于PnC。

感知任务传递给ppnc的时候信息经过高度压缩，bbox, point seq是很显然不够表征复杂现实世界._pnc通过行为对无损传递的感知信息的filter/attention/clea(反正怎么说的都有，核心是对感知任务和信息的选择，info selection)(rule based select不又回到之前的问题了，人为定义任何“硬”的东西感觉都偏离端到端的初衷)，_tesla shadow mode从一开始run的时候就是以行为作为value/cost fitler来设计的。

目前所谓端到端模型在行车中使用的时候，在输出的轨迹之后都会去接一个基于传统方法兜底的方案，或者是这样的learning based planner和传统的轨迹规划算法会同时输出多条轨迹，再通过一个selector来选择一条执行(目前的learning based planner更多的是做evaluator对轨迹进行打分)。

当谈论端到端自动驾驶的时候，我们到底在谈论些什么

  1. 开环评测： 系统被置于一个不受外部反馈控制的环境中，系统的输入被改变以模拟不同的情况，但系统本身的输出不会影响评测环境。例如模型输出的 planning 指令做出了加减速动作，由于路测的感知视频是录制的，这个动作无法反映到图像上去，这导致开环评测只能在每一帧都会重置到数据集中录制那一刻的评测环境，并且是安全的轨迹，不存在误差累积。学术界最常见的就是在 nuscenes 数据集上进行开环评测。

  2. 闭环评测：模型的输出会影响评测环境，同时评测环境的反馈会影响系统的输入，形成一个反馈循环。闭环评测模拟了真实世界中系统与环境的相互作用，例如自车发生变道行为，反应到图像上就是视角切换，前车切换等等，最常用的就是 Carla 模拟器。

Feed-Forward端到端自动驾驶

目前99%基于深度学习的方法都假设了这样的结构，也就是说最终关心的输出量（比如控制信号）u = f(x)，x是传感器的各种观测。在某些问题里，我们希望能够使得最终的输出量满足或接近某些性质，这样Feed-Forward的形式便很难给出这样的保证。所以能还有一种方式我们可以写成u* = argmin g(u, x) s.t. h(u, x) <= c 这样的约束优化形式(控制率本身无法通过模型得到，那么直接将端到端模型本身作为优化器，求解最优控制),在CV领域也有一些工作是试图将这两者的优势结合起来，比如通过Implict Function构造导数的方式

目前各家端到端方案neural的部分只是为后续的优化方案提供了若干初始化的proposal去缓解后续优化高度非凸的问题。这本质上和AlphaGo里的fast rollout做的事情是一模一样的。但是AlphaGo不会把后续的MCTS搜索叫做一个“兜底”方案。

为神经网络的输出添加约束

在RL中一般将约束空间作为状态之一传入网络，输出设置为可在约束空间内进行合理采样的变量，如此能保证输出一定满足约束(每多一个变量就多一个action维度，action维度上升将大大增加训练难度)。但大部分时候约束空间并不好直接描述(有的问题约束能描述准确，但是cost无法描述)，只能将较宽的约束空间传入网络，在采样输出后对输出做约束优化。

如果您熟悉强化学习，那么这种策略对您并不陌生。对一个n维的向量施加约束看起来比较困难，但可以将一个n维的向量拆成n次输出。每次输出的时候，通过人为编写代码，限制下一位变量，使其的值位于可行域内。这种“自回归式”方法的优势显而易见，方法简单、可以处理的约束种类丰富（只要能写出代码，就可以施加对应的约束）。但是其劣势也非常明显，首先一个n维的向量需要调用n次网络前向计算，效率不高；其次这种方法通常需要建模成马尔科夫链的形式、通过强化学习进行训练，那么强化学习中动作空间过大、奖励函数稀疏、训练时间长等常见问题可能也无法避免。

生成模型的设计理念即是输出需要符合特定分布，似乎更适合“学出约束”的思路。Sun “DIFUSCO: Graph-based Diffusion Solvers for Combinatorial Optimization” 展示了Diffusion模型可以输出满足旅行商问题约束的解（即能够输出完整的回路）

通过求解一个凸优化问题，将神经网络的输出投影到凸约束围成的可行域。这里用到了凸优化问题KKT条件可求导的性质，因此这一投影步骤就可认为是一层激活层，能够嵌入在端到端的神经网络中。这一方法论由CMU的Zico Kolter组提出并发扬光大，他们目前提供了cvxpylayers(编写求解器) 这个包可供使用

$ \max_xx^Ty,st. Ax \leq b $** **x为待求的满足约束的变量，Ab为线性或凸约束，y为神经网络输出的无约束结果。通过最大化无约束结果在满足约束的结果的投影实现得到满足约束的结果，其实可以在cost中再加一个x和y的熵正则期望两个分布不要相差过大。

在非连续问题中，当问题参数改变引起解跳变时，实际梯度是一个冲激函数（即无穷大），显然这种梯度没法用于神经网络的训练。所幸，有一些现成的梯度近似方法可以处理这一问题

马普所的Georg Martius组提出了黑盒近似方法Vlastelica ICLR'2020 “Differentiation of Blackbox Combinatorial Solvers”，其核心理念是将求解器视为黑盒，先调用一次求解器，再将问题参数在特定方向上进行一次扰动后再调用一次求解器。两次求解器输出的差可作为梯度的近似。应用到神经网络输出的约束投影上

$ \max_xx^Ty,st. H(x)\in C $** 调用求解器**

你的任务是实现一种算法，去求解上面这个问题（不一定要求到最优解），随后即可套入黑盒近似的框架中

是否存在一种方法，不用解优化问题，直接就可以在GPU上像一层激活层一样完成特定约束的投影,本质上是一个不需要优化求解的直接投影方法

Wang ICML'2023 “LinSATNet: The Positive Linear Satisfiability Neural Networks"就给出了一种可行方案

LinSAT可以被视为一层激活层，您可以将一般的正线性约束应用于神经网络的输出。

** Ax<=b,Cx>=d,Ex=f,A B C E d f >=0**

主车与障碍物协同规划（Co-Leader planning）

障碍物轨迹受主车影响，主车轨迹也受障碍物影响。不同于联合规划的方案，这种规划方案里，障碍物的预测并不是确定性的，主车会综合考虑障碍物的多种不同可能性后选择一个最优解，障碍车也会考虑主车行为后选择障碍车的响应方式

使用边缘预测的规划方案（Planning with marginalized predictions）

【这里作者用的maringalized prediction这个词，含义与之前不少预测论文（如Scene Transformer）中写的marginal prediction不是一个意思】

作者这里的marginal prediction是指不去区分多种不同的未来可能性，而是直接整体考虑所有的可能性。换句话说就是不做显式的多模态预测或者多模态最终给到planner用的时候使用某种手段融合成一个单模态、与主车行为无关的预测结果(比如一个轨迹分布或热力图，但是感觉他车意图还是很重要的，不能直接单模态)给planner用。

考虑最差情况的规划方案 （Worst-case planning ） 这种方案一般是考虑多种模态后，要求被预测出的任意模态的预测一旦发生都要能被规划处理，这种用法里一般在cost函数里不会去使用预测的概率。

应变型规划方案（Contingency planning） 这种方案会考虑每种不同的未来场景的可能性和其发生的概率，对cost函数要求比较高，需要能够对多种概率的安全性和发生概率进行整体的权衡。

特别的，文中讲了有一些方案，可以在短时规划使用worst case planning确保安全，在长时规划中权衡发生概率与安全性。

(CILQR)算法通过障碍函数将不同的约束包含到目标函数中。根据线性关系，约束可以归纳为两类。首先，任何非线性约束都可以通过一阶泰勒展开转化为线性约束。然后，应用barrier function并对其进行二次化。这个过程在(5)和(6)中得到了演示。现在可以将二次化的线性barrier function合并到ILQR算法中。

CILQR的一个缺点是它需要针对特定场景调整特定的权重集。例如，即使目标车辆的速度很高，为超车调整一组权重也总是倾向于鼓励超车。为了提高原始CILQR的通用性，减少对行为级规划的依赖，提出了考虑自我车辆与目标车辆之间状态差异以及目标车辆速度的分析函数。这些函数自适应地计算成本函数权值，并允许规划器在不切换权值的情况下执行多个任务

直观地说，无论目标车辆的速度如何，当前方目标车辆远离自车时，我们都希望保持车道保持行为。当distance gap缩小时，如果目标车辆的行驶速度接近期望的参考速度，则需要车道保持行为。如果相同的目标车辆以较慢的速度行驶，则需要安全的超车机动。因此，行为与目标车辆的速度以及自我车辆与目标车辆的相对距离密切相关.

Based on this observation, weights that affect the velocity and reference tracking term are expressed as follows: 根据这一观察，影响速度和参考跟踪项的权重表示为:

$ \begin{gathered} \omega_{vel}=\frac{a_1}{v_{target}}e^{b_1\delta x}\\ \omega_{ref}=\frac{v_{target}}{a_2e^{b_2\delta x}} \end{gathered} $

其中a1、a2、b1、b2都是权重，delta x为自车与目标车辆的距离(较大时，由于较大的速度权重，鼓励保持速度的行为,较小时 根据目标车辆的速度，分别鼓励慢速车辆超车和快速车辆保持车道)，v target为目标车辆的速度

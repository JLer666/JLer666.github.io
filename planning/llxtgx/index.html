Dijkstra and A*

dijskstra算法和BFS的最大区别是，从容器中弹出节点的规则不同(之前说过好多次了)，BFS是按照遍历节点顺序的先入先出规则(当前容器中节点在树状图中层级最浅的那个节点)来弹出节点。(BFS解决 无向 无权 图 最短路径问题,dijskstra可解决有向带权图问题 但是图中的权值必须全部为正)

dijskstra 通过g(n)计算节点n的代价，每次从容器中弹出g(n)代价最小的那个节点。dijskstra 设计的g(n)为 从起点s出发到当前节点n的累计代价值(累计路径上节点与节点间边的权重)。

同时dijskstra在扩展时除了检查邻接的节点是否曾经被扩展过(BFS也有做，如果扩展过这个节点 就不会放入容器open中)，还会看邻接节点m的g(m)是否可以通过经过n节点后再到m节点这个方式来下降 即 g(n) + n->m边权重 <? g(m) 如果小于则用g(n) + n->m边权重更新g(m)。

dijskstra算法能够保证已经被访问过的节点的g值一定是全局最小的。

优点dijskstra是全局最优的

缺点 dijskstra是基于BFS的(当图的边权值都相等dijskstra退化为BFS)，其搜索特点和BFS一样，是以起点为中心向外扩展(像水面的波纹 下图有画)。均匀地向各个方向扩展–穷举搜索 算法很慢，本质上是因为dijskstra没有考虑终点信息，盲目地 均匀地 向邻居所有节点都扩张。

dijskstra没有目的性没有考虑终点信息，而我们上面讲的贪心算法中的启发函数heuristic考虑了终点信息，结合一下。将dijskstra的弹出规则考虑节点到终点的信息，这就诞生了A。

A == dijskstra(提供最优解保证 从起点到当前节点的最小代价) + heuristic(提供目的性 从节点到终点的接近程度的猜测)*

A*中依旧会维护每个节点n的g(n) 从起点s到节点n的累计代价

同时还会维护每个节点的heuristic，定义节点n的heuristic为h(n) = 节点n到终点g的估计代价(比较常见的做法是用 n到g的欧式距离或曼哈顿距离 作为h(n))

f(n) = g(n) + h(n) 此为每个节点在容器–优先队列–最小堆中的排序依据–弹出规则

A*算法就是BFS+每次弹出容器中f值最小节点。

与dijskstra同样A*在扩展时除了检查邻接的节点是否曾经被扩展过(BFS也有做，如果扩展过这个节点 就不会放入容器open中)，还会看邻接节点m的g(m)是否可以通过经过n节点后再到m节点这个方式来下降 即 g(n) + n->m边权重 <? g(m) 如果小于则用g(n) + n->m边权重更新g(m)。

缺点 A找到的path不一定是全局最优的，g值(到当前节点的累计代价)是实实在在由边的权重决定 不会骗人 最短的路径其累计代价g就是最小的。但是预先设定的估计节点与终点的接近程度heuristic如果设计不好h值就是不准确的,导致f值不准确，导致找到的路径并非全局最优。A算法要保证最优，我们需要设计heuristic使每个节点的h值一定要<= 其节点到终点的最短路径的累积边权重。

对于djistrak算法来说，在搜索的过程中弹出了某一节点，意味着从起点到此节点的最优路径已经找到了。对于A*来说并非如此，要求启发项满足上面的要求，才能保证最优 。

满足条件的最优性证明

欧式距离(sqrt(dx^2+dy^2))作为heuristic衡量节点到终点的接近程度，是一定能保证A*最优，因为两点之间直线最短，欧式距离就是两点间的直线距离，是一定<=节点到终点的实际最短路径长，从下面这张图就能很明显地看出来。

绿色用曼哈度距离(|dx| + |dy|)作为heuristic，不一定能保证A最优。举一个很简单的例子，从(0,0)->(1,1)没有障碍物，实际最短路径距离是sqrt(2),而曼哈顿距离是|1|+|1| = 2。h==2>sqrt(2)实际最短路径代价,所以用曼哈顿距离做heuristic不能保证A的最优性。上面的这个例子是允许机器人对角线移动所以实际的最短路径距离为sqrt(2)，假如不允许机器人对角线移动则其实际的最短路径距离为2,是=曼哈顿距离的，这种情况下用曼哈度距离做heuristic又能保证A*的最优性。

优点 dijskstra是基于BFS的(当图的边权值都相等dijskstra退化为BFS)，其搜索特点和BFS一样，是以起点为中心向外扩展(像水面的波纹 下图有画)。均匀地向各个方向扩展–穷举搜索 算法很慢，本质上是因为dijskstra没有考虑终点信息，盲目地 均匀地 向邻居所有节点都扩张。而A因为用了启发式函数指引逼向终点 目的性更强，所以A的搜索速度要远快于dijskstra。

A* = dijskstra+贪心引导

如果我们设计 h(n)>n节点到终点的实际最短路径代价,算法是在向我们之前讲的greedy best first search贪心算法在演变，我们接受贪心带来的次优路径的好处是搜索速度加快。

基于这种思想有了

weighted A 设计f=g+b*h，b为调整权重* b>1。b越大 搜索到终点的路径越快，但是没法保证路径是最优的。b=1 weighted A退化为 A，b=0 weighted A退化为dijskstra，b非常大 weighted A退化为best first search贪心算法(b越大越贪心)。

weighted A 就是用最优性的降低，换取搜索速度上的提升*。已经证明过weighted A*最终路径的总代价 <= b x最优路径的总代价，但是时间上的提升是非常巨大的。

工程事先上要注意的点

基于栅格地图的路径搜索 邻居的选取有两种4连通(选取节点 上下左右四个栅格作为邻居)和8连通(选取节点 上下左右,左上左下右上右下 八个栅格作为邻居)如下图

邻居的选取方式 将会使 栅格地图变为 图数据结构的结果不同，4连通 则变为图后每个节点只与上下左右四个节点相连，8连通 则变为图后每个节点与上下左右,左上左下右上右下 八个节点相连。

实际在做path finding,c++中用到的容器有std::priority_queue优先队列,std::multimap(允许一键有多值 的 有序映射容器 允许索引访问)

或者用std::vector存储待排序节点，再调用std::make_heap来直接构造一个堆(优先队列 – 堆本来就可以用数组直接实现)

关键 如何选择最合适的启发函数heuristic来计算h

我们的实际机器人在做path finding基本都是用的8连通，允许对角栅格移动。所以根据之前讲的A*最优保证的前提下，不能用曼哈顿距离来做heuristic。

如果用欧式距离做heuristic最后搜索出的路径确实是最优路径，但是扩展很多多余的节点，浪费了很多时间，如下如图

用欧式距离做heuristic和真正的最优启发式函数h相差很远，是不tight的 所以浪费扩展了很多多余的节点。—解释一下 **前面说过要保证A路径最优 需要保证我们设计的节点h值<= 节点到终点实际最短路径的总代价h* ,用欧式距离做heuristic其h确实100%<=h的，但是用欧式距离做heuristic其计算出的h是远小于h的即h和h*相差的太多了，就是上面所谓的不tight**。才导致上面出现扩展了大量的没有必要的节点

有没有最优的启发函数呢，保证h<=h*并且非常的tight。确实是有的

上面蚂蚁在栅格地图上爬从左上到右下的最优路径，由于非常结构化的栅格地图,并且有8连通的限制，是可以直接求解得到的最优解的 小学生都会，这其实是解了一个数学的几何题目。

dx = |n.x - goal.x| dy = |ny - goal.y|

*h = (dx+dy)+(sqrt(2) - 2)min(dx,dy)==h此节点到终点的最短路径的总代价

这个heuristic叫做diagonal(对角线)heuristic,是所有heuristic中最紧(tight)的heuristic。 每一个节点的h==h此节点到终点的最短路径的总代价

关键 tie breaker 打破平衡

我们的搜索结果会存在多条f值总和相等的路径(上图就是证明 两条path长度总和一样但是形状不一样)。

很多节点会具备相同的f值(因为他们是关于起点与终点连线是对称的)如下图菱形的红色横距,因为这两个点关于起终点连线对称，所以两个点到起点的距离相同(g值相同)，到终点的距离相同(h值相同)，导致这两个点的f值相同。当f值相同的节点同时在同容器中时，选择弹出哪个点呢？

因为f值相同(没有倾向性)会按照进入容器的顺序来扩展，先扩展上边那个再扩展下边这个，在bfs中这两个节点相当于同级的，对称节点没有倾向性也会导致，扩展大量的无用节点(没有坚定地选择一边快速地走下去)，如下左图。

下面讲一种很简单的方法来打破这种对称平衡

修改我们的启发式函数计算出来的h值， 在启发式函数计算出h后，如果存在两个节点的f值相等，则我们略微放大其中一个节点的h值

h = h(1+p);p<单步的最小代价/最长路径的期望代价 这样能保证任何两个节点的f值都不相等，这样在搜索时会更加有倾向性地只选择一条路径。

因为地图大小是有界的，所以可以估计地图的对角线是可能存在的最长路径，对角线路径的代价作为最长路径的期望代价

这其实是一种很暴力的做法，增长后可能导致h>h*,导致计算出的路径并非最优路径。特别是对于使用diagonal(对角线)heuristic,其h==h*,只要增长(p/100)%最终的路径就已经一定不是理论上最优的了。diagonal(对角线)heuristic是在没有障碍物情况下的最大h 只要有障碍 diagonal(对角线)heuristic大概率都是小于 有障碍下的h* (有障碍了一定会导致绕远路，或避障加总路径长 其h相比无障碍情况下的h一定是更大的),p对最优性的影响很小。 其结果如上右图

下面再讲几种工程上解决tie break的方法

1 tie break出现在f=g+h值相等处，我们可以在f相等的前提下，对h排序(优先队列f小的先弹出 在f值相等的前提下，h小的先弹出)。

2 事先计算一个hash 坐标(x,y) 值p<单步的最小代价/最长路径的期望代价 我们需要保证每个坐标hash出来的p值都是不相等的。 在计算节点的h值时将这个很小的hash值加上，这也能保证任意两个节点的f值不等 不会出现tie问题

3 倾向于选择起点和终点连线的这条最优路径

dx1 = abs(n.x-g.x) dy1 = abs(n.y-g.y)

dx2 = abs(s.x-g.x) dy2 = abs(s.y-g.y)

cross = abs(dx1dy2 - dx2dy1) – 经过终点直线上等距离的两个点cross是相等的

在计算每个节点的h值时将这个cross值加上

h = h + cross*0.001 — 垂直于起终点连线并经过终点的线上等距离的两个点cross相等，h相等，g相等，f相等

cross将会使最终结果倾向于起终点连线的直线，效果如下图

一切都是为了打破对称性，为了防止出现f相等的情况

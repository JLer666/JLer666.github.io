词嵌入embedding#

transformer最早是用于文本翻译，网络的输入被称为tokens。在文本中token是单次或者单词片段，对于图像或者语音来说token是一小块图像，或者声音片段，token可以简单理解为离散化的信息。

每个token会被转译为一个向量，这个过程就是embedding，embedding可以简单理解为文本的表征学习，对于含义相近的词其向量在高维空间越接近。

被用于训练的英文单词大概5w个，gtp3的embeding向量维度为12288.训练好的embedding在高维语义空间中的表达通过下面这个例子有个直观感受，寿司 + 德国 - 日本 与 德国油煎香肠 的embedding向量很近

同时向量的点积即投影可以用来衡量两个向量的相似程度(越大方向越一致–同义词方向，0为不相关，越小语义差距越大–反义词方向)，下面这个例子就是用 cats - cat来表达一个复数语义向量，可以看到这个复数语义向量和复数单词的点积是大于与单数单词的点积结果。

同时当复数语义与one,two,three点积时可以看到点积结果是越来越大的

注意上面所讲的并非真正的embedding而是token的向量化，token换为数值向量，可能稀疏，也可能稠密。更注重数据表示的直接性，指的是数值表示形式本身,每个向量只能编码单个单词的含义没有上下文信息。

embedding层参数在训练过程中也会被反向传播更新，基于attention等机制使得上下文关联也被更新到embedding层参数中(基于预训练模型微调那embedding层一般冻结)。

上面直观介绍了早期embedding的基本概念，语言模型中的 Embedding本质是将人类语言映射为计算机可以理解的数字向量。为前transformer时代的静态稠密词向量能达到的效果，下面进一步介绍之后embe静态dding的发展

第一阶段：离散表示时代（One-Hot, Bag of Words, TF-IDF）#

在这个极早期的阶段，人们试图用最直观的数学方式来表示词汇。

  • 核心方法： One-Hot 编码（独热编码）。如果词典有 10000 个词，每个词就是一个 10000 维的向量，其中只有该词对应的位置为 1，其余全为 0。
  • 改进与解决的问题： 首次实现了将文本转换为计算机可以处理的数字形式。TF-IDF 进一步加入了词频和逆文档频率的统计信息，解决了“常用词权重过高”的问题。
  • 遗留的致命缺陷：

  1. 维度灾难与稀疏性： 向量极长且极其稀疏，计算效率极低。

  2. 语义鸿沟（Semantic Gap）： 任意两个不同词的 One-Hot 向量内积都是 0。计算机无法知道“国王”和“皇帝”的语义很接近，而“国王”和“苹果”相差甚远。

第二阶段：静态稠密词向量（Word2Vec, GloVe, FastText）一词一意#

2013年前后，基于“分布式假设”（一个词的含义由它的上下文决定）的静态词向量横空出世，引发了 NLP 领域的革命。

  • 新增改进：

  • Word2Vec： 使用浅层神经网络（CBOW 或 Skip-gram 模型）通过预测上下文来训练词向量。

  • GloVe： 结合了全局词频统计和局部上下文窗口。

  • FastText： 引入了子词（Subword）信息（如 n-gram），把词拆开看。

  • 解决的问题：

  1. 降维与稠密化： 将原本数万维的稀疏向量压缩成了几百维（如 300 维）的稠密向量。

  2. 捕捉语义和语法关系： 向量之间可以通过余弦相似度计算距离。甚至出现了上文谈到的神奇的线性关系：$ V(\text{King}) - V(\text{Man}) + V(\text{Woman}) \approx V(\text{Queen}) $

  3. 缓解 OOV（未登录词）问题： FastText 通过子词拼接，可以推断出训练集中没见过的新词的向量。

  • 遗留的致命缺陷：一词多义（Polysemy）问题。无论“苹果”出现在“吃苹果”还是“苹果手机”中，它在词典中对应的向量永远是同一个。它是“静态”的。一旦训练完成，它就退化成了一个固定的查表字典。不管上下文怎么变，提取出来的向量永远是同一个，无法区分“打（篮球）”和“打（酱油）”。

第三阶段：动态上下文感知时代（ELMo）根据上下文确定词义，动态更新#

为了打破“查表字典”的诅咒，动态 Embedding 诞生，2018 年 ELMo（Embeddings from Language Models）模型被提出。

  • 核心机制： 废弃了固定的词表查询。ELMo 使用双向 LSTM（长短期记忆网络）在阅读大量文本时进行预训练。在实际使用时，输入的是整个句子，模型通过 LSTM 的隐藏状态，为每个词实时计算出一个包含周围语境信息的向量。
  • 解决的问题：彻底解决了一词多义问题。此时，在“去银行 (Bank) 存钱”和“坐在河岸 (Bank) 边”中，“Bank”的 Embedding 是完全不同的，因为它们融合了周围不同的词汇信息。词向量不再是预先存在表里的，而是每次输入时动态生成的。
  • 遗留的致命缺陷： LSTM 作为循环神经网络（RNN）的变体，本质上是串行计算的，不仅训练速度慢，而且在处理长距离文本依赖时能力有限（信息在传递过程中会衰减）。

第四阶段：深度预训练上下文向量（Transformer-based: BERT, GPT系列）#

这是 NLP 的“ImageNet 时刻”，Transformer 架构的引入彻底改变了游戏规则。

  • 新增改进：

  • 抛弃了 RNN，采用基于自注意力机制（Self-Attention）的 Transformer 架构。

  • BERT： 使用掩码语言模型（MLM）进行深度双向预训练。

  • GPT： 使用自回归模型进行单向（从左到右）预训练。

  • 解决的问题：

  1. 突破长距离依赖限制： 自注意力机制让句子中的任何两个词都可以无视物理距离直接发生关联。自注意力机制完美解决了长距离依赖，生成的向量不仅包含基础语境，还融合了极度深层的语法与世界常识。此时的 Embedding 已经是高度浓缩的“知识向量”。

  2. 并行计算与大规模扩展： Transformer 极度适合 GPU 并行计算，使得在海量数据上训练超大模型成为可能。

  3. 统一的范式： 预训练模型生成的深层 Embedding 包含了极度丰富的语法、语义甚至常识信息，只需简单的微调（Fine-tuning）就能在各项 NLP 任务中刷新 SOTA（当前最佳性能）。

第五阶段：面向检索与对齐的现代句向量（Sentence-BERT, SimCSE, BGE, OpenAI Text-Embedding）#

既然 BERT 提取的词向量这么好，那我直接把一句话里所有词的向量加起来求平均，或者直接提取 BERT 输出的特殊句首符号 [CLS] 的向量，不就可以代表这句话的语义了吗？

但在实际做文本匹配（比如计算两句话的余弦相似度）时，大家发现效果奇差无比，甚至不如最古老的 TF-IDF 加权或者简单的 GloVe 词向量平均。

这里存在一个著名的现象——各向异性（Anisotropy），也叫“锥形空间坍塌”。 简单来说，BERT 训练出来的句向量，在几百维的超高维空间里，并没有均匀地散布开来，而是全部挤在一个非常狭窄的锥形区域里。 这就导致：哪怕是两句语义完全无关的话（比如“今天天气真好”和“苹果公司的财报发布了”），它们向量之间的相似度可能高达 0.85。所有的句子都长得很像，向量之间“拉不开差距”，自然就无法用于精准的搜索引擎或知识库召回了。

  • 新增改进：
  • 双塔架构（Sentence-BERT）： 专门针对句子级别的匹配进行训练。没有改变 BERT 的内部结构，而是改变了训练方式。采用了“孪生网络（Siamese Network）架构。把句子 A 送进左边的 BERT，句子 B 送进右边的 BERT（左右参数共享），分别得到两个句向量，然后再计算它俩的相似度。
  • 解决： 它使用自然语言推理数据集（判断两句话是蕴含、矛盾还是中立关系）进行了有监督的微调。这就像是硬生生地把挤在一起的向量“拽”开，强迫模型学会区分句子的宏观语义，极大地提高了检索速度和准确率。
  • 对比学习（Contrastive Learning, 如 SimCSE）： 让相似的句子在向量空间中拉近，不相似的推远，优化向量空间的分布。核心思想是“拉近正样本，推开负样本”。以最惊艳的无监督 SimCSE 为例，它巧妙地利用了 Dropout（神经网络中的随机丢弃机制）。同一句话输入模型两次，因为内部丢弃的神经元不同，会得到两个略微不同的向量，这就构成了一对“正样本”；而同一个批次（Batch）里的其他句子，全部视为“负样本”。
  • 这种训练方式像是一个撑开的伞，把挤在锥形空间的向量强制且均匀地推向了整个向量空间的各个角落，彻底解决了“各向异性”问题。
  • 非对称检索与指令微调（Instruction-Tuned, 如 BGE系列, E5系列）： 像大语言模型一样，现代 Embedding 模型（如 BGE 系列）可以接受指令（如“为这个问题寻找答案”），生成特定意图的向量。在真实业务中，我们经常遇到非对称搜索：用户的 Query 很短（如“感冒吃什么药”），但我们要检索的 Document 很长（如一整篇医学报告）。现代 Embedding 模型开始像 ChatGPT 一样接受“指令（Instruction）”。在训练时，会在输入前加上特定的提示词，例如告诉模型：“为这个搜索查询生成表示：[Query]” 或者 “为这段文档生成表示：[Document]”
  • 让同一个模型能够根据不同任务（是做短文本聚类，还是做长文档问答召回）动态调整向量的生成侧重点，实现了意图级别的精准对齐。
  • 俄罗斯套娃表示学习（Matryoshka Representation Learning, 现代 API 如 OpenAI v3）：在工业落地中，向量维度越大（比如 1536 维、3072 维），精度越高，但在向量数据库中的存储和检索成本就越极其高昂。训练时，强迫模型把最重要的宏观语义信息压缩在向量最前面的几十维里，越往后的维度记录的细节越边缘。
  • 在实际部署时，开发者可以根据成本，直接把长向量从后面截断（比如把 1536 维直接砍到 256 维）来使用，而性能只会下降极少一点点。这极大地降低了企业的显存和存储开销。

  1. 极大地优化了语义搜索和匹配的效率与准确率。

  2. 完美适配了 RAG（检索增强生成） 架构和向量数据库，能够精准地从海量文档档中召回相关的上下文。

  3. 支持了超长上下文（Context Window）和多语言的无缝映射。

  • 将整句、整段话压缩成一个高质量的固定维度向量，使得整个语义空间分布均匀、界限分明。

  • 完美支撑了现代 RAG（检索增强生成）技术，让 AI 能够在一秒钟内从千万篇文档中，通过计算向量距离，找出与用户提问最匹配的段落

总体总结#

纵观整个语言模型 Embedding 的发展史，我们可以总结出三条清晰的演进主线：

  1. 表示形式：从离散走向连续。 摆脱了 One-Hot 的高维稀疏，走向了低维稠密的数学向量空间，让“计算语义”成为可能。

  2. 语境感知：从静态走向动态。 从 Word2Vec 查表式的“千篇一律”，进化到了 BERT 等模型的“因地制宜”，实现了词义对上下文的深度感知。

  3. 应用维度：从词级走向篇章级与意图级。 早期侧重于单个词汇的表达，现代技术则致力于把整个句子、段落甚至长文档压缩成高质量的特征向量，并让这些向量能听懂人类的“指令”，直接服务于复杂的语义检索与 AI 系统。

现在的超强 Embedding 模型，已经变成了一个高度封装的“特征提取黑盒”。你丢给它几十万份文档，它能迅速将其转化为规整的向量阵列；当用户提问时，它能在一秒钟内，通过纯数学的距离计算，精准定位到最相关的三段话，喂给大模型去生成答案

3个坐标系与运动学方程

百度apollo(左手系 右偏为正)的控制部分(PID,LQR)来自«车辆动力学及控制»(注意是及不是及其)，英文原版vechicle dynamics and control,作者是R.R.

控制的前提是已有规划提供的路径x,y,theta,kappa,dkappa,v,a。

3个坐标系，世界坐标系，当前车体坐标系，fernet坐标系(可以实现横纵向控制解耦，可分别单独规划)。

左轮和右轮的转向一致，左轮和右轮的轮距相对于运动轨迹可以忽略不计，航向角就是yaw=横摆角+侧偏角(车质心速度方向与x所成角)，因为车轮的材料是橡胶，受力后的形变比较严重是不可忽略的(会发生侧偏)，前轮转角!=对应方向盘转角传动后的命令。

横摆角和航向角都是定义在世界坐标系下，质心侧偏角和前后轮转角是定义在车体坐标系下

建立横向微分方程 — 前轮转角delta_f是怎么影响侧向位移与航向角

几何关系建立(轮胎不变形)–运动学模型，牛顿力学(轮胎变形)–动力学模型

速度瞬心是前轮转角，后轮转角，质心速度 三个物理量 法方向的交点

建立车体坐标系得到，车体坐标系下的微分方程，刚体角速度 = 刚体线速度/刚体到理论速度瞬心的距离

需要进一步推导，得到前轮转角和这些量的关系

根据正弦定理可以得到前轮转角和刚体到理论速度瞬心的距离R的关系

得到了质心和刚体到理论速度瞬心的距离R的关系，但是这样还不够因为车的载重不同质心的位置也会发生改变。所以我们将两式相加得到(a+b)/R,a+b是车的轴距，车在运行过程中轴距是肯定不会变的，没有问题。

下面讲如何快速在全局路径中查找距离最近的匹配点

我们保存上个规划周期找到的匹配点last_mp,以上个周期找到的匹配点为起点向前向后遍历，设车和last_mp距离为l0，如果上个周期车是向全局路径的前向方向运动的,前向遍历一旦出现li+1>li(下个点的距离更远)马上退出li对应的点就是新的匹配点。如果上个周期车是向全局路径的反向方向运动的，向后遍历一旦出现li-1>li(i<0)i(下个点的距离更远)马上退出li对应的点就是新的匹配点。

如何判断车是前向运动还是反向运动？

车和上个周期匹配点的位置向量差d,上个周期匹配点的切向向量tao

d*tao>0 上个周期到这个周期车是沿全局路径向前运动 向前遍历

d*ta0<0 上个周期到这个周期车是沿全局路径向后运动 向后遍历

|d*ta0|<1e-3 车向全局路径的垂直方向运行，匹配点不变和上个周期一样

此方法也有一个问题，只适用于上个匹配点附近只有一个极小值距离的情况，比如下图粉色的点是上个周期的车位置和车匹配点，黑色的点是此时车的位置，下面的绿色点是用上述方法找到的此周期匹配点，上面绿色的点是实际匹配点。但是一般不会出现这种情况，因为规划周期是100ms,即使以50m/s的速度运动，车也只走了5m，而实际5米内的全局路径，是不太可能出现下图这种非常扭曲的几何的情况，即在上个周期匹配点的附近一般只有一个极小值，不会出现下面这种有多个极小值的情况。

横向控制总结

A,B计算就是带公式但是需要注意当vx=0使的奇异性问题,当abs(vx)<0.01我们直接让K=[0 0 0 0],delta = -K*e + delta_f = delta_f在速度很小的时候，横向转角只由前馈控制

Q,R矩阵分别是e误差，u控制量的权重。Q越大算法的性能越好(尽可能地让跟踪误差为0)，但是计算出来的u会比较大牺牲控制的稳定性。R越大，控制量越小，控制减小横向误差的过程会越平缓(慢)，因为控制调整的较慢导致跟踪的精度下降。

在LQR计算时我们认为整车参数近似不变(车的加速度非常大的时候，有很大的惯性力导致前后轮的垂向力分配是不平均的，垂向力的变化将直接导致轮胎侧偏刚度的变化。急速过弯时内侧轮承受的垂向力远大于外侧轮，此时不能再用自行车模型，需要考虑四个轮子的侧偏刚度。在规划时就需要尽可能地避免出现这两种情况的规划)。此时A,B只与vx有关，而dLQR在确定了A,B,Q,R后可以计算出唯一的K，即K也只与vx有关。此时我们可以离散vx的取值范围(0.01m/s-50m/s–180km/h,dv=0.01)，离线计算出所有离散vx对应的K。这样在我们控制时计算速度将大大提高，直接查表vx对应的K即可。在加速时一样可以将前后轮侧偏刚度,vx作为参数构成一个3维表。(apollo中没有查表)

注意我们的LQR并没有做输出的约束，约束输出在一个范围内，也没有对d输出做限制，所以将会导致LQR算出的控制是不光滑，非连续，会产生突变的情况。

9中的fai误差e_fai具有多值性，相差2pi的角是相同的角，在计算u=-Ke+delta_f是与e_fai的大小有关的，如果e_fai相差2pi虽然角度一样但是计算出来的值完全不一样！！

因为fai-theta=-beta侧偏角很小所以在实际计算时e_fai = sin(fai-theta)

我们LQR跟踪的是与参考路径上与车位置最近的匹配点作为跟踪点来计算横向控制。但速度很快时这个跟踪就太滞后了。因为控制的滞后性，我们需要添加预测模块来达到期望的控制效果

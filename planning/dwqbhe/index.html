系统性地解决tie breaker问题的方法：跳点A jump point search–JPS*

上面的解决方法都是工程上的解决方法，JPS可以彻底解决对称搜索问题

JPS的核心就是找到图中的对称性然后打破

look ahead rule

JPS扩展节点时会综合，当前节点的父节点方向(即是从哪个方向扩展到当前节点的)，以及周围(8连通)障碍物的位置来判断哪些邻居是需要扩展的 哪些是不需要扩展的。

下面举几个例子 来详细说明JPS的扩展规则 下图是无障碍物的例子

1 父 ->当前->邻居m的路径总代价<=父->邻居m的最短路径代价才会选择扩展邻居m

左图选择了往5走，选择了4(父)->x->5的路径

JPS会检查，从当前节点到邻居的代价是否小于等于从父节点到邻居的代价，只有是的话才会选择通过当前节点去到那个邻居 (很好理解 从父节点到了邻居代价更小 为什么不直接从父节点去邻居 反而要多此一举父-x-邻居 代价还更大了，完全没必要)

上图不被考虑的灰色节点叫 劣性节点(inferior neighbors)，被考虑可走的节点 叫自然节点(natural neighbros)

1，2，4，6，7都是绝对的劣性节点，4->x->这些节点的代价一定>4->这些节点的代价

对于3,8节点 4->x->这些节点的代价为sqrt(2)+1 == 4->这些节点的最小代价sqrt(2)+1，这里JPS为了打破对称性 也是为了简化搜索 此情况下这样的节点都不会考虑。

对于5节点 4->x->5 == 4->5 == 2，

上右图同理

1，4，6，7，8作为邻居m 6->x->m > 6->m 所以都不扩展 都是劣性节点

2，3，5作为邻居m 6->x->m <= 6->m 所以可扩展 是自然节点

上面两张图就能代表JPS在所有父节点方向下，考虑扩展的所有情况。记住上面两张图

在有障碍物的情况下

在当前节点的周围存在障碍

左图 在无障碍情况下，3是不需要考虑的。 在此情况下3必须考虑，3是一个forced neighbors,在无障碍情况下 到3可以通过4->x->3 == 4->2->3 == sqrt(2)+1,因为有障碍4->2->3这条路堵上了，根据JPS扩展的原则父 ->当前->邻居m的路径总代价<=父->邻居m的最短路径代价才会选择扩展邻居m，4->x->3是从4->3代价最小的路径所以3号在扩展时要考虑

右图 同理，在无障碍情况下 到1可以通过6->x->1 > 6->4->1，但是4号被障碍堵住了，根据JPS扩展的原则父 ->当前->邻居m的路径总代价<=父->邻居m的最短路径代价才会选择扩展邻居m，6->x->1是从6->1代价最小的路径所以1号在扩展时要考虑

总结：记住无障碍lookahead rule的那两张图，在有障碍的情况下，对于无障碍lookahead rule的那两张图中标的劣性节点,重新计算一下 看在有障碍情况下是否有劣性节点的 父->当前->劣性节点 <= 父->劣性节点最短路径的总代价，则这个劣性节点是forced neighbors需要被考虑进扩展中。

JPS一定好于A吗

对于复杂环境 多障碍 有dead end类迷宫的环境，机器人被障碍包围(在多障碍物的区域中存在 很多的关键点有利于搜索的进行 并且优于JPS算法本身 会选择少量的节点加入open容器中 搜索更快)JPS优于A*。 在实际项目中因为机器人的传感器视野有限经常会出现下面的情况，因为有限的视野只检测到相对于地图来说只是很小一部分的障碍，大部分的区域是空旷的 如下图。 根据JPS的look ahead规则(父节点在 绿色方块的左边)会先进行水平和竖直已经对角线的搜索，因为临近障碍会存在多个关键点**，在寻找关键点的中继点时由于地图左边过于空旷没有任何障碍(也就不存在任何关键点)，只有搜索到达边界 搜索才会停止，这浪费了大量时间**。在下图这种机器人处于空旷环境下(无障碍导致没有关键点 导致只有搜索到边界 才会停止 JPS会增加对环境的碰撞查询的次数，碰撞少了反而搜索次数更多了) A是优于JPS的。并且JPS只能用于 uniform grid map(8邻域的边代价是固定的)，如果节点间边的代价不固定–广义的图搜索是用不了JPS的

JPS补充

补充定义一下forced neighbors

n节点是x的邻居，前提x的邻域内有障碍，parent(x)->x->n的路径长度比其他任何从parent(x)->n的路径短，则n为x的forced neighbors。

补充定义一下无障碍情况下的自然节点选择规则

从parent(x)->x为直线移动，若有parent(x)->n的路径长度小于或等于parent(x)->x->n的路径长度，则n不是自然节点。

从parent(x)->x为对角线移动，若有parent(x)->n的路径长度小于parent(x)->x->n的路径长度，则n不是自然节点。

补充定义跳点==中继点==关键点==加入open中的neigh节点

1 起点或终点 是跳点

2 如果x节点其8邻域内有forced neighbors，则x节点是跳点

3 如果父->x节点是对角移动！！！，从x经过 水平或竖直方向移动！！！可以到另外一个跳点则x也为跳点– 父->x对角线 x->n直线, n有forced neighbors。

例如

S->G是对角移动，从G->H是直线移动。H在dir==G->H基础上拥有forced neighbors K所以H是跳点— 3条件满足 所以G也为跳点

左上角是(0,0)。(2,4)->(1,3)是对角线方向，(1,3)->(1,5)是直线搜索，(1,5)有紫色forced neighbors所以(1,5)是跳点— 根据3规则所以(1,3)也是跳点，将(1,3)加入open中。

在jump搜索跳点过程中，优先在直线方向上搜索跳点(根据父->cur 我们可以得到多个自然节点 在这么多自然节点的搜索方向上优先直线搜索，如果直线搜索找到了跳点就不再进行对角线搜索，直线没搜索到再选择对角线搜索)。

        // 只有最后一个方向的正确的拥有 forced neighbor的节点 才是算法需要的

        if( jump(neiIdx, newDir, newNeiIdx) ) // 递归执行 当前节点变为 邻居节点 ，搜索这个邻居节点的newDir这个方向

    // 在jump搜索跳点过程中，优先在直线方向上搜索跳点(根据父->cur 我们可以得到多个自然节点
    // 在这么多自然节点的搜索方向上优先直线搜索，

    // 只要后续对角线上找到forced neighbor则传出那个离forced neighbor最近的对角节点
    return jump(neiIdx, expDir, neiIdx);

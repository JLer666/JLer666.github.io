最稠密的地图形式，结构化排列紧密，可以直接索引得到地图值

Octo map

八叉树地图

将空间中的一个立方体可以分为8个小的立方体，如果立方体中没有障碍信息则这个节点没有子节点，有障碍信息则这个节点有8个子节点(即将这个1/8空间继续分割成8份)，一直递归地切分下去直到将分割到最小障碍立方体这一层。

稀疏，八叉树结构，非直接的索引查询

voxel hashing

一般将三维的一个栅格称为voxel，hashing就是哈希表

(x,y,z)坐标先计算出此坐标在哪个block中，再将block坐标作为哈希键去得到此block的真实内容(1个block是5x5x5 个voxel)，再根据得到的block去取具体哪个voxel

最稀疏的，RGBD三位重建

point cloud map

点云地图 无序 无法索引得值

用于表示非常稠密的障碍信息

TSDF map

Truncated Signed Distance Function

截断有符号距离函数

每个曲面都有一个距离场，距离场描述了空间中点到这个曲面的最近距离，曲面外侧距离为正，曲面内侧距离为负。 构建地图时只关心视锥内曲面的距离场的值，并截断曲面距离场的范围比如只关心2m以内。

ESDF map

Euclidean Signed Distance Function

就是TSDF不截断，关心曲面到空间中所有点的距离(不仅仅是视锥范围内)。

软约束 用到了轨迹到障碍物距离的梯度信息，上面那张彩色地图 就是颜色越接近红色就是越靠近障碍，越接近绿色离障碍越远。

2 path finding基于搜索

图搜索基础

configuration 机器人配置 机器人对于点的一种描述

DOF 机器人自由度 需要最少数量的值去描述一个机器人configuration 对于无人机来说是6 (x,y,z,r,p,y)

configuration space 机器人配置空间 此空间中存在机器人的所有配置 又叫C-space

pose 机器人的任何一个可能位姿在C-space中都被描述为一个点

如何在配置空间中表示障碍物

对于机器人所处的工作空间(朴素的常讲的机器人所处的复杂环境)不同机器人有不同的形状和大小

检查机器人形状和工作空间障碍是否发生碰撞是比较费时费力的，所以选择在配置空间中做规划。

1预处理Wspace2Cspace将机器人变为质点将障碍物进行膨胀

机器人在配置空间C-space中是被表达成一个点(x,y,z,r,p,y)(下图右边)，所以我们亦需要将障碍物在C-space下表达C-obs。此表达需要在planning之前完成。比如下图这个例子，假设机器人都只有2自由度只有x,y，只能在x或y轴平移无法旋转。则我们将矩形机器人的右上角点(圆形机器人的圆心)在Cspace中代表这个机器人，将Cspace中的障碍物膨胀—-原则:Cspace robot point只要落在蓝色膨胀层的外面是一定不会与黑色障碍物发生碰撞的。(其实相当于将workspace的几何机器人形状在障碍物边缘平移得到了这个膨胀层)

转到配置空间后，规划问题变为robot point从起始点到终止点的规划。规划都是在C-free中做，不再需要考虑机器人尺寸了。

图，有向图，权值图

图搜索，需要先构造图，对于栅格地图(左)来说每个像素天然与周围像素相连 本身就已经是张图了。对于基于采样(右)的图搜索问题，需要先在地图上采样可行的节点再将这些节点连通并加上权重使之成为一张图。

图搜索–找到从S节点到G节点的路径

将左边的图写为右边这种搜索树的形式，从S节点递归向下寻找G节点，当找到G节点后回溯之前走过的路径，就得到了从S->G的路径。 但是一般递归最多50层左右，再多就很慢了，而一般的地图又比较大，这样通过构造搜索树来寻找路径的方法是非常慢的。

图搜索算法的核心是维持一个容器，这个容器中保留了我们要或将来打算访问的所有节点，这个容器初始化为起始节点S

循环：

从容器中弹出(remove pop)一个节点，根据我们提前给出的得分函数为这个节点打分

根据事先定义的扩展方法 获得弹出节点的所有邻居节点

将这个节点的所有连通邻居节点都加入到容器中

结束循环(当访问到了G节点 或 容器为空)

图如果是有环的(A<->B)，会出现访问到A将其邻居B加入容器，后面访问到B 将其邻居A加入容器 – 死循环。所以我们需要一个容器(闭集)装所有已经被扩展过的节点。此容器中的节点之后都不会被再加入到那个待访问容器中

按照什么规则来弹出节点能最快地访问到终点G？下面介绍BFS(广度优先搜索 容器:队列 先入先出)和DFS(深度优先搜索 容器：栈 后入先出)

早就会了只讲1次循环

DFS深度优先搜索 每次先弹出当前容器中访问层级最深的那个节点

初始化容器将起始节点S入栈，开始循环 将栈顶元素弹栈，得到top==s,将与top相连的所有节点入栈(入栈顺序在一些算法中也有评价指标来决定 要注意之前已经扩展过的节点不会再入栈)。开始下次循环从栈顶弹栈得到top==d …….

早就会了只讲一次循环

BFS 广度优先搜索 每次先弹出当前容器中访问层级最浅的那个节点(层序遍历，先遍历浅层再遍历深层)

初始化容器将起始节点S入队，开始循环将队首元素弹出，得到top==s,将与top相连的所有节点入队(入队顺序也是有讲究的)，要注意之前已经扩展过的节点不会再入队)。开始下次循环从栈顶弹栈得到top==p …….

BFS和DFS的区别就是所用容器种类不同，导致对节点的遍历顺序不同(栈后入先出 队列先入先出)。DFS深度优先搜索 每次先弹出当前容器中访问层级最深的那个节点，BFS 广度优先搜索 每次先弹出当前容器中访问层级最浅的那个节点(层序遍历，先遍历浅层再遍历深层)。

BFS是以起点为中心向外扩展(像水面的波纹 找到了最短路径)，DFS没找到最短路径而是一条路走到黑。后面的算法基本都是基于BFS搜索

启发式搜索(Heuristic search)(贪心搜索 greedy best first search)

上面讲的BFS和DFS最大的区别就是从容器中弹出节点的规则不同(先入先出 or 后入先出)。而启发式算法的弹出规则更加复杂由人为设定，这种人为设定的弹出规则叫做heuristic。

一个节点的heuristic是那个节点到终点的接近程度的一个猜测(由人来设计评价接近程度的规则)。

greedy best first search每次弹出容器中与终点最接近的那个节点。下图中黄色为用欧式距离(sqrt(dx^2+dy^2))作为heuristic，绿色用曼哈度距离(|dx| + |dy|)作为heuristic。

设计的heuristic指引了我们扩展的方向(目的性强)，同时设计的heuristic应该是易于计算的。因为heuristic的指引(强目的性)，greedy best first search是快于BFS的。但是在有障碍的环境下，虽然BFS慢但可以找到全局最优，而贪心算法常常陷入局部最优(当heuristic没有考虑障碍 对节点到终点的接近程度 的影响)。同时上面所讲的BFS只针对代价均等地图(无权图)，而实际的代价地图都是有权图。

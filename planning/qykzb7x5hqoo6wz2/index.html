FlowMap: Path Generation for Automated Vehicles in Open Space Using Traffic Flow

创建于 2025-03-09 · 最后修改于 2025-03-15 · cant

基于交通流轨迹数据的开放空间路径生成方法，基于他车轨迹形成road。人类司机习惯去往位置区域时跟随其他的人类司机，通过交通流场表达环境TTF(基于流密度和方向)。

RoadMap轻量化的语义建图框架，基于离散带语义信息的点云/占据数据融合全局语义地图。

TrafficFlow基于车载的检测跟踪结果以及与语义点云/占据生成TTF

在线流程中如果车辆进入感兴趣区域，从云端同步TTF，基于TTF规划路径，在规划时考虑交通流、语义地图、舒适性

Traffic Flow:$ b_i^t=(p,l,w) $表示第i量车在t时刻的车载检测跟踪结果，$ p=(x,y,\theta) $车辆中心位置+朝向，l和w分别为车辆bounding box的长和宽，$ b_v $表示车辆v的轨迹序列。

由于基于感知信息，遮挡、感知误差导致出现短寿命轨迹和漂移轨迹，同时也存在一些静止或时长过短的轨迹。预处理按以下指标筛选轨迹(1) 轨迹时长 (2) 轨迹长度 (3) 帧间跳变漂移 (4) 是否与环境碰撞 (5) 轨迹是否跨过完整路口。

基于上述过滤后为每条$ b_v $附加额外信息$ m_v=(l_{entry},l_{exist},p_{start}) $其中$ l_{entry},l_{exist} $分别表示相交的进出路口的多边形边(如下图中的蓝线)，$ p_{start} $为$ b_v $与$ l_{entry} $相交的位置点。

基于$ l_{entry},l_{exist} $边索引$ g_{in},g_{out} $为$ b_v $分组，对每组内$ b_v $的$ p_{start} $进行聚类得到进入点$ p_{e} $(可能存在多个进入点如下图)，进一步根据$ b_v $的$ p_{start} $与$ p_{e} $间距离进行分组得到$ F\lt g_{in},g_{out},p_e\gt $可以理解为基于入口分组的lane级交通流，内含多种模态的轨迹信息。(感觉分组不完全，应该按进出口分组，并且进出点需要extend可能处于进lane和出lane不同的位置上)

论文里说ROI的多边形边缘不精确，在聚类后会将$ l_{entry} $边优化为与多个$ p_{e} $处交通流平均方向的垂向

为每一个$ F\lt g_{in},g_{out},p_e\gt $构建2维栅格地图，每个栅格中包含$ f_{i,j}=(d,\delta_i,\delta_j) $其中d表示压过此栅格的$ b_v $条数(密度，统计栅格密度时，是将车视为boundingbox,只要box压过的栅格密度都+1),$ \delta_i,\delta_j $表示压过此栅格的$ b_v $在此栅格上朝向单位向量，在xy方向上投影的平均值。

全局的TTF结合RoadMap通过空间索引进行在线更新管理，通过FIFO队列各个ROI上的交通流$ F\lt g_{in},g_{out},p_e\gt $，对每个交通流存储可采用较稀疏的方法只存有密度的栅格，当新交通流被观测到，消除较老的交通流(需要使用增量聚类的方法，确保之前轨迹Pe的聚类结果部分，否则重新聚类可能导致重新分组，则相关的交通流都需要更新，或者按进出匹配的方法就不会有这个顾虑，每个in lane/out lane pair作为索引，每个ROI上的TTF数量是固定的)。通过此机制确保交通流最新。当观察到TTF发生显著变化（这种变化通常是由道路施工和道路改道引起的），TTF生成过程就会生成一个地图更新触发信号，然后将其发送给RoadMap。基于交通流的更新触发信号对于检测道路路线的变化非常有用，并且可以作为轻量级制图流程的一个重要补充。
